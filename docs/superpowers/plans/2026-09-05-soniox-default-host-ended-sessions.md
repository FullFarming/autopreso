# Soniox 기본 엔진·호스트 종료 세션 — 요구사항 및 구현 초안

2026-09-05. 상태: 사용자 승인 후 로컬 구현 완료. 검증 범위와 운영 잔여 사항은 [구현 보고](../status/2026-09-05-core-product-implementation.md)에 기록한다.

Gemini 대안 엔진의 공식 문서 근거와 상세 작업은 [Gemini 직렬 연결 구현 계획](2026-09-05-gemini-transcribe-serial-implementation.md)에 있다. 사용자 배정·세션 수명·인증 갱신은 두 계획의 공통 작업으로 한 번만 구현한다.

## Clarification Summary

- 목적: 캡션·Live Call의 번역 품질과 장시간 연속 사용 개선.
- 포함: 캡션, Live Call, 설정. Live Call 내 원문·번역 기록과 종료 후 요약. 언어집은 두 기능을 지원하는 설정.
- 제외: 화이트보드·코치·별도 통역 제품 등 다른 기능의 사용자 진입 및 실행. Soniox STT → Flash 실시간 번역 조합. 기존 저장 데이터의 삭제는 포함하지 않음.
- 사용자/권한: 가입 후 기본 배정은 Soniox 인식·번역. 기존 관리자 승인 흐름 유지. 관리자만 대안 Gemini Transcribe → Flash로 배정 변경. 두 모드에 같은 배정 적용, 다음 제품 세션부터 반영.
- 언어: 기존 최대 3개 유지. 3개 언어 지원을 위해 Soniox 번역 연결을 복수로 구성.
- 데이터: 사용자별 엔진 배정/버전, 제품 세션에 고정된 엔진 및 용어집 버전. Live Call의 접근 만료와 제품 종료 분리 필요.
- 정상: Soniox로 시작 → 시간 제한 전에 연결 교체 → 같은 세션·기록으로 지속 → 호스트 종료 시에만 종료.
- 실패 A: 최대 연결 시간 도달·일시적 끊김 → 즉시 첫 재연결, 같은 엔진 유지, 연결 상태 표시, 기존 기록 유지.
- 실패 B: 재연결 중 호스트 종료 → 연결 시도·타이머·버퍼 취소, 늦은 응답 무시, 재시작/중복 요약 방지.
- UI: PC 캡션/Live Call/설정, 웹 Live Call 참가·기록, 관리자 배정. 기존 반응형 화면과 DESIGN.md를 사용.
- 외부: Soniox 실시간 API, Gemini 대안 경로 및 요약, Supabase 인증·기록, 기존 게이트웨이.
- 성공: 3개 언어에서 실시간 Flash 호출 0건(Soniox 배정 시), 신규 사용자 Soniox, 300분/6시간 경계에도 제품 세션 유지, 호스트 종료 후 새 연결 0건.
- 롤백: 변경 단위별 코드 복원 및 새 마이그레이션으로 정책 복원. 기존 기록·컬럼 삭제 금지. 운영 적용은 별도 배포 명령 필요.

## 공식 API 근거

- Soniox는 같은 연결에서 인식과 번역을 제공한다. one_way는 대상 언어 하나, two_way는 언어 쌍이다. 3개 언어는 현재 어댑터의 단일 two_way로 해결되지 않는다. [실시간 번역](https://soniox.com/docs/translation/stt-translation/rt-translation)
- 연결당 300분 제한이 있고 연속 사용은 새 연결을 열어야 한다. 공개 문서의 기본 동시 연결 한도는 10개지만 실제 계정 한도는 별도 확인 대상이다. 복수 언어와 교체 중 연결도 한도를 소비한다. [한도](https://soniox.com/docs/stt/rt/limits-and-quotas)
- max_duration_reached와 service_unavailable은 새 연결로 복구하는 경우다. 오류 분기는 문자열 메시지가 아니라 error_type을 사용한다. [오류 처리](https://soniox.com/docs/stt/rt/error-handling)

## 현재 코드와의 차이

1. 기본 카탈로그는 Gemini이고 Soniox 결합 번역은 정확히 두 언어만 허용한다: `packages/caption-core/caption-engine-catalog.js`.
2. 데스크톱 Soniox는 290분 교체 타이머가 있다: `src/caption-engine/soniox-transport.js`, `src/subtitle-realtime.js`.
3. 게이트웨이도 약 289분 30초 경과 후 오디오를 받을 때 교체하지만 sendAudio 오류는 terminalError로 고정한다: `media-gateway/src/rolling-speech-session.js`.
4. Live Call은 별도로 6시간 접근 만료를 생성하고 SQL도 상한을 강제한다: `webapp/lib/live/service.ts:32`, `supabase/migrations/202608310001_live_session_persistence.sql:25`.
5. 현재 관리자 설정 저장은 진행 세션을 일괄 변경한다. 이번 정책에서는 배정 저장이 현재 세션에 영향을 주면 안 된다.

## 아키텍처 결정 제안

### 모델과 기능

- 실시간 사용자 선택지는 개별 STT/번역/요약 모델 조합이 아니라 관리자가 배정한 Soniox 또는 Gemini 엔진으로 단순화한다.
- Soniox 배정 중에는 자막 생성·교정 때문에 Flash를 부르지 않는다. 결정적 용어 검증은 유지한다.
- 요약은 원문 기록을 입력으로 별도 생성한다. 요약 키/모델 실패가 Soniox 자막 시작을 막지 않도록 실시간 키 검증에서 분리한다.
- 신규 사용자 Soniox 배정은 기존 사용자 배정을 자동 덮어쓰지 않는다.

### 최대 3개 언어

- 두 언어는 기존 two_way 경로를 재사용한다. 세 언어는 대상 언어별 one_way 연결을 기본 후보로 한다.
- 오디오는 동일한 시간 기준으로 분배하고 원문은 지정된 한 경로만 권위 있게 저장한다. 다른 연결의 전사로 원문을 중복 저장하지 않는다.
- 별도 연결의 문장 경계가 같다고 가정하지 않는다. 공통 오디오 구간·finalize 경계와 언어별 상태로 대응을 관리하는 프로토타입을 먼저 검증한다.
- 한 언어 연결만 끊겼을 때 정상 언어 자막을 멈추지 않는다. 누락된 언어를 완료된 것처럼 표시하지 않는다.
- 연결 수 증가는 인식 입력 과금과 동시 연결 한도에 영향을 주므로, 3개 언어와 연결 교체의 실제 사용량을 측정한다.

### 호스트 종료와 재연결

- 제품 세션과 공급자 WebSocket 연결을 분리한다. 공급자 교체·인증 토큰 갱신·네트워크 재연결은 같은 제품 세션이다.
- 최대 시간 직전에 연결을 교체하고, 예기치 않은 시간 제한 종료는 즉시 첫 재연결을 시도한다. 반복 실패는 간격을 두고 재시도하며 상태를 보여준다.
- 권한 거부·잘못된 키·할당량 소진을 단순 시간 만료처럼 무한 호출하지 않는다. 제품 상태는 오류/재연결 대기로 유지하며 호스트 종료 여부와 구분한다.
- 잠깐의 재연결은 제한된 오디오 버퍼로 복구한다. 긴 단절을 무제한 메모리에 쌓거나 오디오를 대량으로 급전송하지 않는다. 복구 불가능한 구간은 누락 사실을 기록한다.
- 호스트 종료는 새 연결 금지와 취소 신호를 먼저 설정하고 기존 스트림의 마지막 결과를 제한된 시간 내 정리한다. 반복 종료 요청은 같은 결과를 반환한다.
- 앱 접근 만료는 호스트 활동에 따른 갱신 또는 별도 접근 임대로 설계한다. 만료된 인증 토큰을 허용하거나 expires_at을 임의의 먼 미래로 바꾸는 방식은 사용하지 않는다.
- 호스트 연결이 사라지면 유료 처리는 멈출 수 있지만 제품 세션을 자동 완료 처리하지 않는다. 복귀는 같은 세션으로 가능해야 한다. 사용자 승인 철회·보안 차단은 계속 유효하다.

## 작업 분해와 검증 기준

| 순서 | 담당 | 파일 경계 | 완료 조건 |
|---|---|---|---|
| 1 | Backend | `packages/caption-core/soniox-protocol.js`, 신규 다국어 계약과 테스트 | 3개 언어 원문 1회·번역 각 1회, 불일치/순서 역전 처리 |
| 2 | Backend Desktop | `src/caption-engine/`, `src/subtitle-realtime.js`, 대응 루트 테스트 | Soniox 단독, 교체/복구/종료 경합 검증 |
| 2 | Backend Gateway | `media-gateway/src/engines/`, `rolling-speech-session.js`, 게이트웨이 테스트 | 복수 연결 수명 관리, 언어별 복구, seq 연속 |
| 3 | Schema | 신규 `supabase/migrations/`, bootstrap 미러 | 기존 데이터 보존, 6시간 경계 접근 연속, 종료 상태 보호 |
| 4 | Backend Auth | `webapp/lib/console/`, `lib/live/`, 관련 API | 신규 Soniox 배정, 다음 세션 고정, 요약 키 독립 |
| 4 | Security | 인증·배정·접근 갱신 검토 | 사용자 간 배정 우회/종료된 세션 부활/토큰 재사용 차단 |
| 5 | Design | `public/subtitle*`, 웹 Live Call/설정/콘솔 컴포넌트 | 3개 기능 진입, 관리자 배정 표시, 연결 상태·용어집 개선 |
| 6 | CTO Review | 통합 검토·집중/전체 테스트·로컬 시연 | 정상 1개 및 실패 2개 이상 시연, 미해결 위험 보고 |

같은 파일을 두 작업이 동시에 수정하지 않도록 1번 공통 계약을 먼저 확정한다. 스키마 변경과 API 연결도 순차 진행한다. 다른 세션의 수정은 덮어쓰지 않는다.

## 적대적 검증

- 가상 시계로 Soniox 300분, Gemini 10분, Live Call 6시간 경계 초과.
- 재연결 중 종료, 이중 종료, 늦은 open/final 응답으로 세션이 부활하지 않는지.
- 3개 언어 중 하나만 실패, 번역 응답 순서 역전, 재전송 중복 및 원문 중복.
- 신규 가입 기본 Soniox, 관리자 배정 변경 전후 현재/다음 세션 차이.
- Soniox 사용 시 Flash 번역·교정 호출 0건, 요약 설정 누락에도 자막 정상 시작.
- 인증 만료 갱신, 승인 철회 차단, 타 사용자 세션 접근 거절.
- 긴 무음은 종료가 아니며, 호스트 소멸 시 과금 연결은 정리되고 기록은 유지되는지.
- 기존 용어집의 번역 금지 저장 충돌과 2~3번째 언어 편집 검증.

실제 연결 품질·계정 동시 연결 한도와 운영 DB 적용은 아직 검증하지 않았다. 이 문서는 구현 승인 전 검토 가능한 범위를 고정하는 초안이다.
