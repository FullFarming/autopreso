# 문서 기반 용어 추천과 자막 출력 제어

2026-09-05. 상태: 공식 문서·현재 코드 검토 및 디자인 시안. 이 문서의 신규 기능은 아직 구현하거나 배포하지 않았다. 사용자가 요청한 시안 논의의 후속이며 기존 작업 트리는 유지한다.

## 확정 요구

- 승인된 어닝콜형 참여자 화면에서 번역 본문의 좌우 여백을 줄인다. 글자를 작게 만들어 폭을 확보하지 않는다. 모바일 본문 12~16px 여백과 16/24 기본 글자 크기를 실제 화면에서 검증한다.
- 용어집 입력은 PDF 업로드와 Google Drive 문서 선택을 지원한다.
- AI는 고유명사·전문용어·약어·제품명 등 인식/번역에 유용한 후보를 추천한다. 사용자는 **추천을 확인한 후 중복·충돌 없이 등록**한다. 자동 등록하지 않는다.
- 용어집 모달은 헤더 / 스크롤 본문 / 고정 하단으로 구성한다. 작은 화면에서 등록·닫기가 가려지거나 가로 스크롤에 의존하지 않게 한다.
- 오프라인 자막은 로컬 화면에 표시한다. Live Call은 웹 자막·기록을 유지하면서 로컬 자막 표시 여부를 선택한다.
- 컨트롤러는 MacBook 내장 화면을 우선한다. 자막은 기본적으로 내장·연결된 확장 화면에 모두 표시하고 컨트롤러에서 화면별로 선택한다.
- 표시 변경은 세션/엔진 재시작이나 추가 번역 호출을 유발하지 않는다. 호스트가 종료할 때 제품 세션이 종료된다.

## 공식 문서 확인과 연결 방식

`gemini-3.5-transcribe-live`는 음성을 문자로 변환하는 실시간 모델이다. PDF 분석 모델과 구분한다. Live API에 PDF 전체를 넣거나 번역 사전 전체를 시스템 프롬프트로 넣는 연결이 아니다.

| 단계 | 연결 계약 |
|---|---|
| 문서 확보 | 로컬 PDF 또는 사용자가 Drive Picker에서 선택한 PDF/Google Docs |
| 후보 추출 | PDF 지원 Gemini Flash 모델로 구조화 후보 추출. 현재 추출기는 `gemini-3.7-flash:generateContent` 사용 |
| 검토 | 기존 등록본·이번 가져오기 후보 간 동일 항목 병합, 다른 번역 충돌 분리, 출처 확인 |
| 등록 | 사용자가 선택한 검토 완료 항목만 새 용어집 버전으로 저장 |
| Gemini 인식 | 승인본의 원어·별칭에서 선별한 어휘를 `inputAudioTranscription.customVocabulary`로 전송 |
| Gemini 번역 | 확정 원문을 기존 Flash 번역 경로로 전달하고 대상 언어별 대응표·원문 유지 규칙 적용 |
| Soniox | 기본 엔진 유지. 해당 엔진의 인식·번역 경로에 같은 승인 용어집을 변환해 적용 |

Live 연결 설정은 `models/gemini-3.5-transcribe-live`, `generationConfig.responseModalities: ["TEXT"]`, `inputAudioTranscription: { languageCodes, mode: "VERBATIM", customVocabulary }`이다. 입력은 16kHz·16bit·mono PCM. 부분 응답은 미리보기, 확정 응답은 원문 기록으로 분리한다. 최대 1,000개 어휘를 받지만 공식 권장에 맞춰 관련성이 높은 약 100개를 우선한다. 어휘는 인식 편향 힌트이며 특정 표기의 인식을 보장하지 않는다.

공급자 연결은 최대 10분이다. 현재 약 9분 교체 경로를 유지하고 새 연결에도 **같은 제품 세션의 승인 용어집 버전**을 다시 전송한다. 라이브 연결 중 어휘 변경 지원을 가정하지 않는다. 용어집 수정은 다음 제품 세션부터 적용한다.

출처: [Live Transcribe](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe), [WebSocket API](https://ai.google.dev/api/live), [PDF 처리](https://ai.google.dev/gemini-api/docs/document-processing). 현재 PDF 가이드 예제의 모델명만 보고 기존 문서 분석 모델을 자동 교체하지 않는다. 실제 계정의 모델 이용 가능 여부·비용 검증은 별도이다.

## Google Drive

- 호스트의 Google 회원가입과 문서 접근 권한 요청은 분리한다. `Google Drive에서 선택`을 누를 때 선택 파일에 대한 접근을 요청한다.
- Picker와 `drive.file` 범위를 사용하며 전체 Drive를 검색·수집하지 않는다.
- PDF는 Drive `files.get`의 미디어 다운로드, Google Docs는 `files.export`의 PDF 출력으로 기존 추출 경로를 사용한다. Google Docs PDF 내보내기는 10MB 제한을 고려한다.
- OAuth state는 사용자·작업에 묶고 한 번만 사용한다. Electron은 시스템 브라우저의 인증/선택 흐름을 사용한다. 선택 문서 가져오기만 수행하며 지속 동기화·백그라운드 접근은 범위 밖이다.
- 클라이언트가 임의로 준 URL을 서버가 다운로드하지 않는다. 파일 ID로 실제 MIME·다운로드 권한을 확인한다. 문서 안의 명령·URL은 자료로만 취급한다.
- 파일/모델 업로드 및 임시 파일은 작업 수명에 맞춰 정리한다. 외부 서비스에 실제 사용자 문서를 보내는 시연은 아직 하지 않았다.

출처: [인증과 인가](https://developers.google.com/identity/oauth2/web/guides/how-user-authz-works), [Drive 범위](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [다운로드와 내보내기](https://developers.google.com/workspace/drive/api/guides/manage-downloads), [Picker 설정](https://developers.google.com/workspace/drive/picker/guides/web-picker-sample).

후보 중복 키는 정규화된 원어·언어·번역과 의미/문맥을 고려한다. NFC·여백 등 안전한 정규화는 적용하되 대소문자가 의미를 바꾸는 약어·제품명과 동음이의어를 무조건 합치지 않는다. 서로 다른 후보 ID를 붙이는 것만으로 중복 제거를 완료했다고 보지 않는다.

서버가 `importId`, 파일 식별/수정 버전, 내용 해시, 추출 모델, 원어/대상 언어를 관리한다. AI가 만든 페이지·근거를 검증된 출처로 단정하지 않으며, 출처 문장 확인이 안 되면 해당 상태를 표시한다. 동일 문서 재수입과 등록 더블 클릭도 멱등 처리한다.

## 구현 순서와 담당 경계

### 컨트롤러 자막 실시간 조절 추가 확정 요구

사용자는 출력 컨트롤러의 디자인·위치를 수용하고 자막 위치·글자 크기·배경 투명도를 실시간으로 조절하도록 요청했다.

- 기존 `자막` 버튼에 자막 설정 팝오버를 연결한다. `출력` 버튼의 화면 선택과 구분하고 두 팝오버를 동시에 열지 않는다.
- 자막 위치는 상단·중앙·하단을 즉시 선택한다. 선택된 로컬 출력 화면의 자막 전체에 적용하며 다국어 줄이 서로 겹치지 않도록 배치한다.
- 글자 크기는 슬라이더와 숫자 표시로 조절한다. 시안의 24~72px는 범위 제안이며 실제 지원 범위·언어별 줄 넘침을 검증한다. 큰 글자 때문에 현재 발언이 잘리지 않게 한다.
- 배경 투명도는 0% 불투명에서 100% 완전 투명까지 일관된 의미로 표시하는 방향이다. 글자 자체는 투명해지지 않는다. 내부 배경 alpha는 `1 - transparency / 100`으로 변환한다.
- 현재 opacity 허용 범위는 0.2~1이며, 0까지 확장하려면 저장·검증·렌더링 전 경계를 변경해야 한다. `Number(settings.opacity) || default`가 0을 잘못 기본값으로 치환하는 경로도 수정해야 한다.
- 현재 컨트롤러는 `input` 이벤트에서 숫자만 갱신하고 `change`에서 명령을 전송한다. 요구대로 드래그 중 실제 자막이 바뀌도록 최신 값 우선 전송을 구현한다. 디스크 저장은 묶어서 처리하되 조작 종료의 마지막 값을 반드시 보존하고 늦은 응답이 최신 값을 덮지 않게 한다.
- 별도 저장·적용 버튼 없이 반영한다. 실패하면 저장/적용 완료로 표시하지 않고 실제 상태를 재동기화한다. 텍스트·회의·원문 기록·번역 연결은 유지한다.
- 여기서 조절하는 대상은 PC 오버레이다. 참여자 웹의 개인 글자 크기나 스크롤 위치를 호스트 설정으로 강제 변경하지 않는다.
- 화면 가장자리에서는 팝오버 방향을 바꾸거나 본문만 스크롤한다. 닫기·Escape·포커스 복귀를 보장한다.

### 작업 분담

1. Backend: 후보 ID·중복·충돌 계약과 실패 테스트. 추출기·공통 문서 처리·API, 임시 파일 수명. 기존 파이프라인 유지.
2. Security: Drive 권한과 선택 파일 조회·OAuth 경계. 문서 추출과 독립 개발하되 검증된 파일 바이트/메타데이터 계약으로 통합.
3. Schema: 필요한 import provenance 저장 구조를 기존 JSON 스키마와 비교 후 추가형 변경. 기존 데이터 기본값·마이그레이션 명시. 즉시 컬럼 삭제 없음.
4. Design: 새 추천 모달·기존 선택 모달의 스크롤/포커스, 참여자 본문 폭. API 계약 확정 후 연결.
5. Desktop: Electron 화면 배치·출력 설정·IPC와 테스트. Design은 컨트롤러 뷰 파일을, Desktop은 메인 프로세스/정책을 소유해 충돌 방지.
6. Gateway/Backend: Live Call 결과를 선택한 화면에 재사용하고 세 언어·원문 표시·재연결 시 용어집 버전 검증.
7. CTO 통합 검토, 아래 적대적 검증, 실제 브라우저/장치 시연. 설정 준비 후에도 배포는 별도 명시 명령 필요.

## 적대적 검증 계획

| 위험 | 검증 기준 |
|---|---|
| 후보 유실·중복 | 두 PDF 연속, 동일 PDF 재수입, 이중 클릭, 동시 저장: 기존 후보 보존·중복 행 0건 |
| 의미 손상 | 다른 번역·다른 우선순위·동음이의어·유니코드: 미해결 충돌 자동 덮어쓰기 0건 |
| 문서 외부입력 | 잘못된 MIME·10MB 초과·과도한 페이지·시간 초과·악성 지시: 명확한 실패, 자동 승인 없음 |
| 권한 우회 | 타인 Drive 연결·state 재사용·다운로드 금지·권한 철회: 읽기/등록 거절 |
| 공급자 교체 | 9~10분 교체·동시 goAway·호스트 종료: 동일 어휘 버전, 종료 후 새 연결 0건 |
| 모달 | 375×568, 390×844, 768×568, 큰 글자/키보드: 등록 접근·가로 넘침 없음·Esc/포커스 복귀 |
| 화면 배치 | 외장 기본 화면, 음수 좌표, 혼합 배율, 덮개 닫기/열기, 모니터 탈착: 컨트롤러 접근 유지 |
| 비용·세션 | 출력 토글 반복: 인식/번역 호출 증가 없음, 웹 기록 지속, 새 제품 세션 생성 없음 |

현재 검증은 공식 문서·소스 읽기와 디자인 검토이다. 위 런타임 테스트는 아직 실행하지 않았다.
