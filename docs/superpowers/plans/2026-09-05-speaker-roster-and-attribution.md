# 사전 발언자 명단 및 호스트 발언자 제어

상태: 로컬 구현 및 검증 완료. 실제 DB 적용과 배포는 미실행. 아래 조사·예시 검증 내용은 구현 전 기록이며, 최종 구현 및 적용 절차는 [구현 결과](../status/2026-09-05-speaker-roster-implementation.md)를 기준으로 한다.

## 확정한 흐름

- 현장에서는 호스트가 발언자를 직접 지정한다. 목소리·얼굴로 사람을 자동 식별하지 않는다.
- Live Call 준비 중 이름과 선택 사항인 사진·회사·부서를 등록한다. 사진이 없으면 이름 첫 글자를 표시한다.
- 온라인 참여자와 사전 명단의 연결은 호스트가 확인한다. 이름이 같다는 이유만으로 자동 연결하지 않는다.
- 온라인 참여자가 실제 발언권을 얻으면 연결된 프로필을 표시한다. 미연결 참여자는 기존 입장 이름과 기본 아이콘을 표시한다.
- 온라인 발언이 끝나면 선택해 둔 현장 발언자로 돌아온다. 현장 발언자 선택과 온라인 마이크 발언권은 별도 상태다.
- 데스크톱 컨트롤러 및 웹 호스트 관리 화면에서 제어한다. 앞서 승인한 태블릿 QR·진행 전용 화면은 계속 읽기 전용이다.
- 발언 당시 사진·이름을 원문·번역·기록에 보존한다. 이후 명단을 수정해도 과거 발언은 소급 변경하지 않는다.

## 디자인 예시

`output/2026-09-05-speaker-roster-preview/index.html`의 세 화면으로 검토한다.

| 화면 | 구성 |
| --- | --- |
| 준비 | 사진·이름 목록, 발언자 추가·수정, 온라인 참여자 연결 |
| 호스트 진행 | 현재 발언자, 현장 발언자 선택, 온라인 발언권 상태, 전환 결과 |
| 참여자 화면 | 사진 아이콘·이름과 넓은 자막 본문, 발언별 기록 |

디자인 예시는 브라우저 메모리에서만 동작한다. 사진은 서버로 업로드되지 않고 새로고침하면 초기화된다. 샘플 인물·대사와 온라인 발언권 조작은 검토용이다. 실제 회의에 연결되었다고 표시하지 않는다.

### 예시 화면 검증 결과

- 브라우저에서 세 탭 이동, 온라인 프로필 발언권 부여·회수, 현장 프로필 복귀, 예시 자막 추가를 확인했다.
- 김민지의 표시 이름을 긴 이름으로 바꾼 뒤에도 기존 네 개 발언 기록의 이름이 유지되는 것을 확인했다.
- 375×568에서 모달이 화면 안에 표시되고, 1024×768에서 가로 넘침이 없음을 확인했다. 중복 닫기 버튼을 제거하고 Escape 닫기도 확인했다.
- 이름에 HTML 이벤트 문자열을 입력했을 때 이미지 노드가 생성되지 않고 문자 그대로 표시되는 것을 확인했다.
- 예시 JavaScript 문법 검사 및 작업 공간 공백 오류 검사가 통과했다. 제품 코드는 변경하지 않았으므로 제품 전체 테스트를 새로 실행하지 않았다.
- 실제 사진 파일 선택·업로드 서버, 실제 발언권·음성 처리·인증은 이번 디자인 예시 검증 대상이 아니다. 운영 기능 완료나 보안 검증 완료를 의미하지 않는다.

화면 증거: 같은 예시 폴더의 `tablet-host.jpg`, `mobile-viewer.jpg`, `mobile-dialog.jpg`.

일반 버튼은 최소 44px·반경 8px, 모달은 화면 안에서 본문만 스크롤, 사진은 원형으로 표시한다. 긴 이름은 줄바꿈하고 자막 본문 폭은 유지한다. 사진 실패 시에도 이름을 계속 표시한다.

## 기존 코드에서 확인한 제약

1. `media-gateway/src/gateway-server.js`는 온라인 발언권을 실제 participant/grant와 연결한다. 현장 인물을 가짜 participant로 넣으면 음성 권한과 DB 참조가 잘못된다.
2. `media-gateway/src/live-media-pipeline.js`의 `setFloorSpeaker`는 현재·직전 발언자와 유예 시간을 사용한다. 발언 시작 시각이 없는 공급자 응답 및 A→B→C 급속 변경에서 정확성을 보장하기에 부족하다.
3. `webapp/components/live/SpeakerCaption.tsx`와 `public/subtitle-overlay.js`는 현장 음성을 `Host`로 고정 표시한다.
4. `webapp/lib/live/store.ts`, `media-gateway/src/supabase-adapters.js`의 재접속 기록 복원도 함께 수정해야 한다. 실시간 화면에만 사진을 추가하면 재접속 후 정보가 사라진다.
5. 기존 `session_speakers`는 STT 화자 색·음성용 테이블이다. 사전 명단과는 목적 및 제약이 다르므로 재사용하지 않는다.

## 구조 결정

### 회의별 명단

별도 명단 엔티티를 추가한다. `speakerId`, `sessionId`, `displayName`, `photoAssetVersion`, 선택적 `linkedParticipantId`, 변경 `revision`을 갖는다. 같은 이름 두 명도 서로 다른 ID로 구분한다. 기존 세션의 명단은 비어 있는 것이 기본값이다.

프로필과 이미지 버전을 불변 자료로 보관하여 발언 기록이 참조한다. 삭제는 신규 선택 목록에서 제외하는 방식이며, 기록이 참조하는 사진을 즉시 삭제하지 않는다. 보존 기간은 기존 회의 기록 정책과 맞춘다.

### 현재 발언자

`activeOnsiteSpeakerId`와 기존 온라인 floor holder를 분리한다. 온라인 발언권이 있으면 해당 참여자의 연결 프로필을 사용하고, 없으면 현장 선택을 사용한다. 연결·이름 변경 자체가 마이크를 켜거나 기존 발언권을 빼앗지 않는다. 온라인 연결 변경도 이후 발언 구간부터 적용한다.

호스트의 제어 요청은 소유권을 확인한 API로 받고, revision을 비교하여 오래된 요청을 거부한다. 오디오를 송출하는 게이트웨이가 변경을 적용한 뒤에만 UI를 변경 완료로 표시한다. 요청 실패 시 이전 선택을 유지하고 오류와 재시도 행동을 보여준다. 웹 관리 화면이 발언자를 바꾸기 위해 두 번째 HOST 음성 소켓을 만들면 안 된다.

### 자막 귀속

핵심 선행 작업은 오디오 수신 경계에 `identityEpoch`와 불변 화자 스냅샷을 붙이는 것이다. 결과가 도착한 시점의 현재 선택자로 자막을 덮어쓰지 않는다.

공급자가 발언 시작·끝 오프셋을 제공하면 캡처 구간과 매핑한다. 오프셋이 없는 경로는 공급자 스트림 세대와 발언자 전환 경계를 함께 나눠 이전 스트림의 늦은 결과가 이전 프로필을 갖도록 해야 한다. 전환 시 오디오 유실, 중복 final, 번역 seq 회귀를 방지하는 배수·버퍼 처리와 완료 확인이 필요하다. 단순 타이머나 직전 발언자 한 명만 기억하는 방법을 정확성 보장으로 사용하지 않는다.

정확한 공급자별 전환 방식은 아래 첫 구현 단계에서 검증한다. 경계를 증명하지 못한 상태로 사진 UI만 운영 경로에 연결하지 않는다.

현행 `acceptAudio`에는 캡처 화자 인수가 있지만 STT의 `sendAudio(frame)`까지 그 정보를 운반하지 않는다. 인수 존재만으로 정확한 귀속이 구현되어 있다고 판단하면 안 된다. 수신 PCM 오프셋 구간과 스트림 세대별 epoch 원장을 함께 연결해야 한다. 한 마이크의 동시 발화 또는 시각 정보 없는 한 결과 안에 두 사람이 섞인 경우는 호스트 선택만으로 자동 분리할 수 없다. 경계가 불확실하면 현재 사람에게 임의 귀속하지 않고 ‘발언자 확인 필요’ 상태를 보존한다.

## 구현 순서와 파일 소유권

| 단계 | 담당·경계 | 완료 조건 |
| --- | --- | --- |
| 1 | Gateway: `live-media-pipeline.js`, provider adapters, attribution tests | 늦은 A 결과가 B·C 선택 후에도 A로 남음. 재연결·번역 대기에도 동일 |
| 2 | Schema: 새 Supabase 마이그레이션·RPC·RLS | 기존 데이터 보존, 같은 회의 연결 검증, revision 충돌 거부 |
| 3 | Backend: 별도 roster store/validation/API/photo 경로 | 소유권·사진 검증·동시성 테스트, 서버 적용 확인 |
| 4 | Design/Desktop: `public/subtitle.html`, `subtitle-workspace.js`, controller 및 Electron IPC | 준비·사진 등록·현재 발언자 선택. 컨트롤러 창 크기 유지 |
| 5 | Design/Web: 별도 roster/picker 컴포넌트와 `LiveHostDashboard.tsx` | 같은 명단과 현재 상태 사용, QR 전용 화면 읽기 전용 유지 |
| 6 | 계약·기록 통합: `live-contract.ts`, gateway persistence, web replay, local archive, CaptionEntry·SpeakerCaption·overlay | 실시간·새로고침·원문·기록에서 동일한 이름·사진 |

독립 파일은 병렬 작업하고 계약·스키마·공급자 경계가 확정되기 전에는 의존 구현을 시작하지 않는다. 실제 데스크톱 수정 대상은 `public/`이며 루트의 과거 사본을 복원하지 않는다. Canvas 저장소 및 3319 실행 서비스는 이번 기능과 무관하다.

## 적대적 검증 계획

| 시나리오 | 기대 결과 |
| --- | --- |
| A→B→C 연속 선택 후 A의 늦은 final | A 프로필 유지, 발언 순서와 seq 보존 |
| 온라인 발언 중 현장 선택 변경 | 온라인 표시·오디오 권한 유지, 온라인 종료 후 새 현장 선택으로 복귀 |
| 두 호스트 화면이 동시 변경 | 한 revision만 성공, 나머지는 충돌 표시 후 서버 상태 조회 |
| 다른 회의 speaker/participant ID 삽입 | 403 또는 404, 변경 없음 |
| 참여자가 호스트 선택 API 직접 호출 | 거부, 마이크 권한 상승 없음 |
| 같은 이름 두 명 | ID별 선택·기록 분리 |
| 사진 MIME 위장, SVG, 초대형 픽셀, 외부 URL | 서버에서 거부, 기존 프로필 보존 |
| 사진 교체·명단 삭제 후 과거 기록 조회 | 당시 프로필 유지 또는 명시적 보존 정책에 따른 기본 아이콘 |
| 인증 만료·네트워크 단절·변경 중 회의 종료 | 완료로 오인하지 않음, 세션 재시작 없음 |
| 375px 휴대폰·1024px 태블릿·긴 이름·키보드 | 모달/버튼/자막 잘림 없음, 초점 복귀 |

## 배포·운영

현재 단계에는 운영 설정 변경이 없다. 실제 구현 후에는 Supabase 추가 마이그레이션·사진 저장소 정책·웹·게이트웨이·데스크톱을 호환 순서로 반영해야 한다. 사진 URL을 임의 외부 주소로 받지 않는다. 명단 사진은 해당 회의의 승인된 참여자 및 소유 호스트에게만 제공한다.

배포는 별도 사용자 요청 후 수행한다. 롤백은 새 UI·API 진입을 비활성화하고 추가 데이터를 유지하는 방식으로 하며, 즉시 컬럼이나 기록을 삭제하지 않는다.

기존 cover 이미지 GET은 공개 서명 주소로 리디렉션하는 경로이므로 인물 사진에 그대로 복제하지 않는다. 사진 제공 경로에서 실제 회의 접근 권한을 확인하고, 단기 서명 URL 및 캐시 정책을 별도로 검토한다.
