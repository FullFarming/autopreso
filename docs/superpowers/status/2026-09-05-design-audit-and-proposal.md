# NOVA 전체 화면 디자인 감사 및 개선안

작성일: 2026-09-05. 요청 범위: 기존 화면 분석과 개선안. 제품 코드 수정·배포 없음.

## 결론

우선순위는 **모달 잘림·키보드 이탈 수정 → 중복 기능 정리 → 컴포넌트 규격 통일 → 화면별 배치 정돈**이다. 새 기능이나 전면적인 색상 변경보다, 이미 있는 캡션·Live Call·설정의 흐름을 단순하게 만드는 편이 효과적이다.

직접 확인한 주요 결함은 용어집 모달의 저장 버튼 잘림, 모달 밖으로 빠지는 키보드 포커스, 오디오 설정 카드의 내용 넘침이다. 캡션의 두 용어집 선택 체계와 관리자 배정 옆 개인 API 키 입력도 제품 정책을 혼동시킨다.

## 범위와 근거

- Product Design index → audit, 프로젝트 DESIGN.md 사용. 디자인·모달 구조를 별도 에이전트가 읽기 전용 검토하고 현재 브라우저 화면과 대조했다.
- 이번 감사에서 새로 저장하고 직접 열어 확인한 스크린샷만 시각적 근거로 채택했다. 이전 작업의 통과 보고나 화면은 재사용하지 않았다.
- 데스크톱: 로컬 fixture의 `subtitle.html`. 실제 Electron 권한·오디오·로그인 연결은 검증하지 않았다.
- 웹: 별도 개발 서버의 로그인·참가자 입장·기록 데모·참가자 데모. Supabase 연결은 자식 프로세스에서 로컬 주소로 대체했다. 계정 생성, 실제 세션 시작, 키 저장, 발송은 하지 않았다.
- 관리자 콘솔은 로그인으로 리다이렉트되었다. 인증을 우회하지 않았으며 웹 호스트 관리 화면·관리자 확인 모달·QR·웹 용어집 등록은 정적 분석 범위다.
- 화면 크기는 CSS viewport 기준이다. 실제 iPhone/iPad, 모바일 키보드, 200% 브라우저 확대, 모든 UI 언어는 미검증이다.
- Lazyweb 워크플로를 확인했으나 추가 참고 조회는 요청 한도(429)로 제한되었다. 외부 디자인 사례를 이번 결론의 근거로 삼지 않았다.
- 리사이즈 직후 임시 프레임(05), 비정상 전체 페이지 합성(13)은 시각적 근거에서 제외했다. 파일명 번호는 캡처 순서이며 아래 문서 순서는 제품 사용 흐름이다.

### 1. 로그인·회원가입

회원가입 시 제목·설명을 상태에 맞춰 변경한다. Google과 이메일은 두 인증 방식이므로 중복 기능으로 삭제하지 않는다. 하나의 폼 컴포넌트에서 동일한 필드 간격과 높이를 쓰고, 이메일 폼의 제출 버튼을 충분히 식별되게 한다.

![회원가입에서도 로그인 제목이 남는 현재 화면](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/04-signup-desktop.jpg)

375×568에서 폼은 세로 스크롤로 가입 신청까지 도달했다. 화면 아래에 있다는 이유만으로 잘림 결함으로 판정하지 않았다.

![작은 화면에서 스크롤로 도달한 가입 신청](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/17-signup-mobile.jpg)

### 2. 참가자 입장

‘이름을 입력하면 바로 참여’ 대신 실제 필요한 정보를 설명한다. 초대 링크로 코드가 채워지는 경우와 직접 코드 입력 경로를 구분하고, 선택 정보는 기존 펼침으로 유지한다. ‘관리자로 로그인’은 일반 호스트도 사용하는 경로이므로 ‘호스트로 로그인’이 명확하다. 동의 항목 자체의 삭제는 이번 디자인 개선에 포함하지 않는다.

![참가자 입장 화면](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/14-watch-entry.jpg)

### 3. 캡션

1280×800에서 자막 언어 선택은 약 y=667, 세션 용어집 선택은 y=779에 있다. 큰 미리보기 아래에 핵심 준비 작업이 밀려 있다. 대기 상태 미리보기를 줄이고 **언어·용어집·입력 확인·시작**을 첫 화면 안에서 읽도록 재배치한다. 미리보기 높이를 단순히 고정하기보다 창 높이에 맞춰 제한한다.

![캡션 첫 화면](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/01-caption-desktop.jpg)

캡션에는 ‘이번 세션 용어집’ 선택만 남긴다. 기존 프리셋의 언어쌍·도메인·용어 설정은 관리 화면으로 옮겨 통합한다. 마이그레이션 전에는 두 체계의 저장값이 보존되고 충돌 없이 변환되는지 확인해야 한다.

![동시에 노출된 세션 용어집과 기존 프리셋](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/11-caption-options-desktop.jpg)

하단 제어는 세션 상태에 따라 주 버튼을 바꾼다. 대기 중에는 ‘자막 시작’, 실행 중에는 ‘자막 종료’, 복구 중에는 ‘다시 연결 중’과 종료 액션을 제공한다. ‘다시 시작’은 필요한 실패 상태의 보조 동작으로 제한한다. 오버레이 표시 여부는 세션 종료와 다른 기능이므로 별도로 유지하되 상태와 스위치를 가까이 묶는다.

### 4. 용어집 상세 모달

![데스크톱 용어집 상세](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/20-glossary-desktop.jpg)

![375×568에서 저장 버튼 하단이 잘린 모달](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/21-glossary-small.jpg)

작은 화면의 DOM 측정: 모달 top=16.5, bottom=536.5, clientHeight=518, scrollHeight=575, overflow=hidden. 저장 버튼 top=509, bottom=557로 모달 경계를 넘는다. 768×568에서는 저장 버튼 bottom=500.5로 모달 안에 들어왔다. **모든 크기에서 잘린다는 결론은 아니다.**

검색창에서 Shift+Tab 두 번 후 포커스가 배경의 `overlay-enabled`로 이동했다. 모달 닫기 후 원래 ‘자세히’ 버튼으로 복구되지 않았다.

개선: native dialog 또는 동일한 접근성 계약을 가진 공통 Dialog 사용. 높이는 viewport 최대값으로 제한하고, 본문은 `min-height:0`과 내부 스크롤을 허용한다. 작은 높이에서는 검색·목록·추가 폼을 스크롤 가능한 본문에 넣고 닫기/저장 동작의 도달성을 확보한다. 배경은 inert, Escape 닫기, 트리거로 포커스 복구를 공통 처리한다.

### 5. PC Live Call

![Live Call 준비 화면](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/19-livecall-desktop.jpg)

준비 화면 순서를 제목 → 출력 언어 최대 3개 → 용어집 → 오디오 확인 → 시작으로 정리한다. 커버 이미지·예약·정원은 보조 설정으로 묶는다. ‘바로 시작 / 예약’ 선택에 맞춰 주 버튼을 한 개로 표시하며, 진행 중 화면에는 공유·참여자·자막·호스트 종료를 집중 배치한다. ‘기록·요약’은 이 기능의 하위 진입으로 유지한다.

캡션과 Live Call의 시작 버튼 색이 현재 다르게 보인다. 기존 액션 색 토큰을 공유하고, 핵심 버튼을 페이지마다 별도의 색으로 정의하지 않는다.

### 6. 설정

![오디오 카드 밖으로 나온 미터와 상태](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/15-settings-general.jpg)

오디오 카드 실제 폭은 220px인데 내부 scrollWidth는 364px이다. 행의 최소 열 폭 합계가 카드보다 커 미터와 상태가 바깥으로 나온다. 카드가 폼의 값 영역 전체를 차지하게 하고, 좁은 폭에서는 오디오 이름·미터·상태를 두 줄로 재배치한다.

![관리자 배정과 개인 키 입력이 함께 있는 고급 설정](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/18-settings-advanced.jpg)

설정은 **계정·오디오·자막 표시·용어집**으로 분리한다. 배정 엔진은 계정 안에서 읽기 전용으로 표시한다. 일반 사용자에게 개인 API 키 입력과 원문 프롬프트 편집을 노출하지 않는다. 필요한 운영 기능은 관리자 콘솔로 옮기고, 실제 개발용 설정이 필요하면 별도로 제한한다. 번역 어투·주제 모델은 선택된 엔진에서 실제로 효과가 있는 경우에만 노출한다.

### 7. 기록·요약

![PC 기록의 달력 화면](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/23-desktop-records.jpg)

![웹 기록 상세 데모](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/07-records-desktop.jpg)

![웹 기록 AI 요약 데모](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/08-records-summary.jpg)

기록 탐색의 기본값을 최근 세션 목록으로 제안한다. 날짜 필터·검색은 유지하고 달력은 보조 보기로 둔다. 세션 상세는 원문·번역·요약을 우선 배치하며 참여자·수신 신청자 관리는 권한이 있는 호스트 영역에 둔다. 현재 상단 Excel 내보내기는 전체 회의 기준이라고 명확히 설명하고 있으므로 탭별 버튼으로 불필요하게 복제하지 않는다. 데모 제어줄의 높이는 실제 제품의 결함으로 계산하지 않았다.

### 8. 참가자 자막·더보기

![짧은 화면의 참가자 자막 데모](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/09-viewer-mobile.jpg)

![작은 화면 안에 들어오는 더보기 시트 데모](/Users/kyeongmankim/Realtime/autopreso/output/2026-09-05-design-audit/10-viewer-drawer-mobile.jpg)

데모는 실제 자막 읽기·ControlDrawer 컴포넌트를 사용하지만 실제 회의 연결 검증은 아니다. 375×568에서 더보기 모달 top=161, bottom=568, clientHeight=scrollHeight=405로 화면 내에 들어온다. Escape 후 ‘더보기’로 포커스 복귀도 확인했다.

짧은 높이에서는 상단 회의 정보의 여백을 줄여 자막 읽기 영역을 확보한다. ‘실시간으로 돌아가기’는 자막 문장 위를 덮지 않는 위치를 확보한다. 발언 버튼의 상태명은 시각적으로도 알 수 있게 하고, 고정 하단 영역이 마지막 자막을 덮지 않게 여백을 예약한다.

## 기능·버튼 정리 원칙

- 최상위: 캡션 / Live Call / 설정. 관리자에게만 별도 콘솔 진입.
- 기록·요약: Live Call 하위 유지. 캡션 기록은 필요 시 같은 목록에서 유형으로 구분.
- 용어집: 세션 화면은 선택만, 설정은 등록·검색·편집·충돌 관리.
- 로그인: Google과 이메일은 유지. 역할 판정은 서버가 수행하며 관리자 전용 로그인 폼을 중복 생성하지 않음.
- ‘시작/종료’, ‘바로 시작/예약’, ‘오버레이 표시/세션 종료’, ‘QR 전체 화면 종료/모달 닫기’는 서로 다른 의미다. 삭제보다 상태별 노출을 정돈한다.
- 주 액션을 하나로 모아도 호스트 종료는 재연결 중을 포함해 항상 도달 가능해야 한다. 참가자의 발언 종료는 회의 종료와 구분한다.
- 모델 배정 변경은 다음 세션부터 적용되므로 설정·콘솔 확인 문구를 동일하게 유지한다. 화면 정리로 3개 언어 지원을 축소하지 않는다.

## 구현 순서·검증 조건

1. 모달과 오디오 카드의 실제 결함부터 수정. 새 공통 Dialog를 기존 용어집 상세에 먼저 적용해 검증한다.
2. 용어집 중복 UI 및 사용자 키 입력 경로 정리. 기존 저장값 보존·선택 엔진별 유효 설정을 먼저 확인한다.
3. FormControls·Dialog·StatusBadge·Tabs 규격을 문서와 코드에 고정하고 화면별 중복 CSS를 정리한다.
4. 캡션 준비 화면·Live Call 준비/진행·설정·기록 배치를 순차 적용한다.
5. 실제 관리자 로그인 후 콘솔·QR·웹 등록 모달을 추가 시연한다. 전체 완료 판정은 이 단계 이후다.
