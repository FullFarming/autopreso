# 사전 발언자 명단 구현 및 적용 안내

작성: 2026-09-05. 상태: 로컬 구현·검증 완료, 실제 DB 적용·운영 배포 미실행.

## 구현 범위

- Electron 준비 화면과 웹 호스트 관리 화면에서 이름·사진·회사·부서 등록, 수정, 명단 제외 및 실제 온라인 참여자 연결.
- 현장 발언자는 호스트가 직접 선택한다. 데스크톱 컨트롤러에서도 선택할 수 있다.
- 온라인 발언권자가 명단에 연결되어 있으면 해당 프로필, 연결되지 않았으면 해당 참여자의 입장 이름을 표시한다. 선택된 현장 인물로 대신 표시하지 않는다.
- 온라인 발언 종료 후 선택해 둔 현장 발언자로 복귀한다. 태블릿 QR·진행 전용 화면은 계속 읽기 전용이다.
- 실시간 자막·오버레이·원문·번역 데이터·기록 복원에 발언 당시 프로필 버전을 보존한다. 프로필 수정이 과거 기록을 덮어쓰지 않는다. 기존 기록 화면의 원문·요약 구성을 유지한다.
- 오디오 수신 시점과 공급자 연결 세대를 기준으로 발언자를 귀속한다. 귀속 근거가 부족한 결과는 ‘발언자 확인 필요’로 표시한다.
- 저장 충돌과 인증 만료는 명시적으로 처리한다. 데스크톱 명단 저장 재시도는 이미 생성한 회의를 재사용한다.
- 긴 이름·회사·부서는 줄바꿈하며, 작은 화면의 편집 모달은 본문만 스크롤한다. 사진이 없거나 표시되지 않으면 이름 첫 글자를 사용한다.

## 사용자/운영자가 적용할 순서

1. 기존 Supabase 마이그레이션 적용 현황을 확인하고 개발 환경에 먼저 아래 순서로 적용한다.
   - `supabase/migrations/202609050003_live_speaker_roster.sql`
   - `supabase/migrations/202609050004_speaker_profile_history.sql`
2. 첫 파일은 회의별 명단, 비공개 사진, 불변 프로필 버전 및 소유권·revision 검사 RPC를 추가한다. 두 번째는 원문·번역 저장 및 조회에 프로필 이력을 연결한다. 기존 회의는 빈 명단에서 시작한다.
3. 새 프로젝트용 `supabase/bootstrap-new-project.sql`에도 두 파일을 포함했다. 이미 구성된 DB에는 전체 bootstrap을 다시 실행하지 않는다.
4. DB 준비 후 같은 변경 버전의 미디어 게이트웨이와 웹앱을 적용하고 Electron을 갱신한다. 웹앱 설치 의존성에 사진 재인코딩용 `sharp`가 직접 명시되어 있다. 기존 lockfile을 사용해 설치한다.
5. 실행 중인 로컬 NOVA 서버도 재시작해야 새 정적 자산 허용 목록이 반영된다. 기존 음성 세션이 끝난 뒤 재시작한다.
6. Vercel을 사용하는 경우 기존 웹앱 프로젝트의 빌드·배포 절차를 사용한다. 이 기능만을 위한 새 환경 변수나 별도 외부 이미지 저장소 설정은 없다. 기존 인증·Supabase 서버 설정은 필요하다. 서비스 자격 증명은 브라우저에 제공하지 않는다.
7. 실제 개발 계정 두 개와 테스트 회의에서 소유권, 사진 업로드, 온라인 연결, 현장 전환, 재접속 기록을 확인한 뒤 운영 적용을 결정한다.

이 작업에서는 실제 Supabase에 SQL을 적용하거나 Vercel·게이트웨이를 배포하지 않았다. 비밀번호·API 키를 변경하거나 코드에 추가하지 않았다.

## 검증 결과

- 루트 테스트: 1,500 통과, 19 건너뜀, 실패 0.
- 웹앱: Live 1,021 + Core 77 = 1,098 통과, 실패 0.
- 게이트웨이: 617 통과, 실패 0.
- 세 프로젝트 합계: 3,215 통과. 건너뛴 테스트를 통과로 계산하지 않았다.
- SQL 별도 검증: PGlite 4 통과. 전체 마이그레이션 순서, 소유권, 명단 변경 충돌, 프로필 불변성, 종료 상태를 검사했다. 플랫폼 전용 기능은 테스트 대체 구현을 사용했으므로 실제 Supabase 적용 검증을 대체하지 않는다.
- 루트·웹 타입 검사 및 변경 내용 공백 검사 통과. 루트에는 별도 lint 스크립트가 없다.

### 적대적 검증

| 항목 | 결과와 근거 |
| --- | --- |

| A2 권한 | 호스트 소유권, 다른 회의 사진, 위조·취소된 참여 권한, 비인증 요청 거부 테스트 통과 |

| A7 잔류 상태 | 과거 프로필 불변, 종료 후 변경 거부, 인증 상실 시 편집 상태 제거, 미연결 온라인 발언자 오귀속 방지 테스트 통과 |

브라우저 시연은 실제 컴포넌트·렌더러와 로컬 모의 API/IPC를 사용했다. 실제 로그인·클라우드 DB·패키징된 Electron·물리 마이크·유료 모델 장시간 송출 검증은 포함하지 않는다. 임시 검증용 웹 컴포넌트와 경로는 원복했다.

화면 증거: `output/2026-09-05-speaker-implementation/mobile-editor.jpg`, `desktop-host.jpg`, `desktop-controller.jpg`. 데스크톱 화면 하단의 생성·저장 횟수 표시는 검증용 표시이며 제품에는 없다.

## 남은 제약과 되돌리기

한 마이크에 여러 사람이 동시에 말하면 호스트 선택만으로 모든 음성을 확정할 수 없다. 근거가 모호한 구간은 미확인으로 남긴다. 공급자 연결을 바꾸는 경로는 실제 모델 환경에서 전환 지연을 추가 확인해야 한다.

문제가 생기면 새 회의 시작을 중단하고 호환되는 이전 앱·게이트웨이 버전으로 되돌린다. 추가된 테이블·프로필 이력은 보존하며 즉시 삭제하지 않는다. 진행 중인 회의와 기록 복원 호환성을 개발 환경에서 확인한 뒤 롤백한다.
