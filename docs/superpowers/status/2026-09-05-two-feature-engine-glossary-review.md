# NOVA 두 핵심 기능·사용자별 엔진·용어집 개선 평가

평가일: 2026-09-05. 코드 확인 기준 HEAD: `949b06f`. 원본 상태 문서 기준은 `f784cd9`이므로 진행 상태를 구분한다. 이번 산출물은 분석 보고서이며 제품 코드 수정·배포 결과가 아니다.

**후속 사용자 결정:** Soniox → Flash 실시간 번역 조합은 제품 선택지에서 제외한다. 신규 사용자 기본 엔진은 Soniox 자체 인식·번역이며 자막 언어는 기존 최대 3개를 유지한다. 기능은 캡션·Live Call·설정으로 제한하고 기록·요약은 Live Call에 포함한다. 공급자 연결 제한으로 제품 세션을 끝내지 않으며 호스트 종료까지 재연결한다. 아래 초기 평가의 선택지보다 [후속 요구사항 및 구현 초안](../plans/2026-09-05-soniox-default-host-ended-sessions.md)이 우선한다.

## 확정한 방향

- 오프라인 자막은 인터넷을 사용하는 PC 로컬 자막을 의미한다.
- 핵심 기능은 로컬 자막, Live Call 두 가지다. Live Call은 PC 자막과 웹 자막·기록을 제공한다.
- 직렬 연결은 Gemini Transcribe Live 음성 인식 후 별도 텍스트 번역 호출을 의미한다.
- 관리자가 사용자별 엔진을 배정하고 로컬 자막과 Live Call 모두에 적용한다.
- 배정 변경은 **다음 세션부터** 적용한다. 현재 세션과 그 재연결은 시작 시 설정을 유지해야 한다.

## 기존 작업 평가

엔진 카탈로그·어댑터 팩토리, 원문과 번역 기록 분리, 확정 자막에만 seq 부여, 용어집 버전 고정·충돌 검사, 가입 승인과 관리자 콘솔은 재사용할 가치가 있다. 새 엔진 기반을 다시 만드는 것보다 배정 정책과 두 제품 경로의 일관성을 정리하는 것이 우선이다.

원본 문서의 미완료 목록 중 게이트웨이 엔진 전환, 콘솔의 진행 세션 일괄 적용, 데스크톱 재연결 시 엔진 갱신, 정합성 커밋은 현재 코드에 들어 있다. 다만 이 즉시 전환 정책은 이번에 확정한 정책과 다르다. 운영 배포와 마이그레이션 적용 여부는 이번에 조회하지 않았다.

## 공식 문서와 직렬 연결

### Gemini

`gemini-3.5-transcribe-live`는 공식 모델이다. TEXT 모달리티, PCM 16kHz mono 입력, 부분/확정 전사 필드가 문서화돼 있다. 언어 코드는 힌트이며 강제 제한이 아니다. customVocabulary는 최대 1,000개, 일반적으로 100개 이하를 권장한다. 세션은 최대 10분이며 실시간 화자 분리·단어별 타임스탬프는 지원하지 않는다. 출처: [Live Transcribe 가이드](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe).

권장 경로: 음성 → Transcribe Live → 확정 원문 → Gemini Flash 텍스트 번역 → 용어 규칙 검증 → 자막과 기록. 부분 결과는 미리보기, 확정 결과는 기록으로 취급한다. 인식과 번역은 직렬이지만 다음 음성 수신을 이전 번역 완료까지 멈추면 안 된다. 번역 완료 순서가 바뀌어도 발언 식별자·순번으로 원문 대응을 유지한다.

현재 `media-gateway/src/google-provider-adapters.js:183`에 TEXT/VERBATIM/언어 힌트/용어집 설정이 있고, `media-gateway/src/engines/create-engines.js:78` 및 `:99`가 STT와 번역기를 연결한다. 즉 연결 기반은 이미 구현되어 있다.

기존 기본 번역 모델 `gemini-3.6-flash`는 텍스트 출력과 구조화 출력을 지원하며 Live API 모델은 아니다. 별도 텍스트 호출로 사용하는 구조가 맞다. 출처: [Gemini 3.6 Flash 모델](https://ai.google.dev/gemini-api/docs/models/gemini-3.6-flash).

### Soniox

Soniox STT → Gemini Flash도 현재 팩토리 구조상 가능하다. Soniox 자체 인식+번역은 별도 결합 경로다. 제품은 two_way 두 언어만 구현했지만 공식 API 자체는 one_way도 지원하므로 ‘Soniox는 무조건 두 언어만 가능’이라고 일반화하면 안 된다. 원문과 번역 토큰도 일대일 대응이 보장되지 않는다. 출처: [실시간 번역](https://soniox.com/docs/translation/stt-translation/rt-translation).

`language_hints_strict`도 완전한 언어 보장은 아니다. 카탈로그의 `canRestrictSource`가 보장 의미로 읽히지 않도록 표현과 테스트를 고쳐야 한다. 출처: [언어 제한](https://soniox.com/docs/stt/concepts/language-restrictions).

## 사용자별 배정 설계 제안

1. 사용자 ID에 엔진 선택·배정 버전·변경 관리자·변경 시각을 저장한다. 기본값은 명시적으로 배정을 생성할 때 사용한다.
2. 로컬 자막 시작과 Live Call 생성에서 동일한 서버 정책으로 배정을 검증한다. 사용자 요청 본문의 모델값은 권위로 사용하지 않는다.
3. 세션에는 엔진과 배정 버전을 복사해 고정한다. 재연결·10분 인식 연결 교체는 새 세션이 아니므로 현재 배정값을 다시 가져와 덮어쓰지 않는다.
4. 관리자 콘솔에서 ‘현재 세션 엔진’과 ‘다음 세션 배정’을 구분한다. 기존 전역 ‘배포’ 액션은 일반 배정 저장 흐름에서 제외한다.
5. 관리자 관리형 키는 서버에 보관한다. 데스크톱 직접 공급자 연결을 유지할 경우 공급자별 단기 자격 증명의 제한 범위를 확인한다. Gemini 전사는 모델/config 제한 토큰이 문서화돼 있지만 별도 Flash 번역 호출까지 같은 토큰으로 된다고 가정하지 않는다.

동시 관리자 수정은 배정 버전 비교로 충돌을 알린다. 정책 조회 장애 시 임의 엔진 전환을 하지 않는다. 기존 실행 중인 세션까지 중단해야 한다는 의미는 아니다.

## 두 핵심 기능으로 축소

- 사용자 주요 진입: 로컬 자막 / Live Call.
- Live Call의 PC 표시·웹 표시·저장은 같은 확정 자막 이벤트를 사용한다. 같은 호스트 음성을 로컬 엔진과 게이트웨이가 각각 번역해 결과가 달라지거나 중복 과금되는 흐름을 검사한다.
- 기록은 Live Call의 결과로 연결하고, 용어집과 계정은 지원 설정으로 둔다. 관리자 콘솔은 관리자 역할에만 제공한다.
- 화이트보드·코치·음성 출력은 사용자가 요청한 핵심 범위 밖으로 분리하는 것을 제안한다. 파일을 먼저 대량 삭제하지 말고 실행 진입과 의존성을 확인한다.
- 공유할 것은 엔진 계약·용어집·이벤트 의미다. Electron과 게이트웨이의 실행 수명·인증 경계까지 하나로 합칠 필요는 없다.

Design 검토는 기존 `DESIGN.md`와 [Lazyweb 화면 참고자료](https://www.lazyweb.com/agentic-search/2ed573e7-24a8-48b4-ab4a-560ff061ab8b)를 사용했다. 현재 제품의 실제 화면 시연이나 시각 품질 점수 평가는 수행하지 않았다.

## 용어집 개선

기존 구조화 문서에는 원문, 언어별 번역, 별칭, 발음, 번역 금지, 금지 번역, 문맥, 예시, 우선순위가 있다. 모델을 다시 만들기보다 편집기와 공급자 전달 과정이 이 구조를 온전히 사용하도록 개선한다.

1. 첫 번째 언어만 편집하는 제약과 번역 금지 항목 저장 충돌부터 수정한다.
2. 원문·언어별 번역·별칭을 기본 편집으로, 발음·금지 번역·문맥·예시를 필요할 때 펼치는 편집으로 제공한다.
3. 동일한 구조화 문서에서 인식용 어휘, 번역용 언어별 대응표, 확정 결과 검증 규칙을 각각 생성한다. 긴 자유 텍스트를 모든 모델에 동일하게 보내지 않는다.
4. Gemini는 고유명사·우선순위 기반 소수 어휘 선택을 유지한다. Soniox는 기존 레거시 문자열 재해석 대신 구조화 문서에서 `terms`, `translation_terms`, `general`을 생성하도록 개선한다. Soniox 공식 context 한도는 8,000 tokens이며 문서의 약 10,000 characters는 근사치다. 출처: [Soniox Context](https://soniox.com/docs/stt/concepts/context).
5. 세션 시작 시 용어집 버전도 고정하는 것을 제안한다. 수정이 진행 중 자막이나 기존 기록을 소급 변경하지 않게 한다.
6. 평가 항목은 필수 용어 정확도, 잘못된 강제 치환, 번역 금지 준수, 언어별 누락으로 나눈다. 약어·동음이의어·한영 혼용·숫자와 단위·한글 정규화 사례를 포함한다.

## 검증 범위와 후속 순서

이번 직접 실행: 루트 엔진/용어집/재연결 집중 테스트 43개, 게이트웨이 팩토리/Soniox/용어집 보안 테스트 36개 통과. 별도 검토 에이전트가 웹앱 권한·콘솔·push 28개 및 게이트웨이 관리자 전환 4개를 통과했다고 보고했다. 팩토리 중복 실행분은 합계에서 제외한다.

전체 스위트·클린 체크아웃·브라우저 시연·실제 마이크·장시간 공급자 연결·운영 DB는 이번 평가에서 검증하지 않았다. 기존 테스트 통과가 새 배정 정책이나 번역 품질의 완성을 의미하지 않는다.

추천 실행 순서:

1. 이번 사용자 결정을 기존 전역 즉시 전환 스펙보다 우선하도록 요구사항 정리.
2. 용어집 저장 충돌과 Soniox 언어 불일치 수정 및 재현 테스트.
3. 사용자 배정 저장 → 로컬/Live Call 시작 정책 → 세션 고정 및 재연결 검증.
4. 두 핵심 진입과 다국어 용어집 편집 정리.
5. 동일 음성 fixture로 공급자별 정확도·첫 자막/확정 번역 지연·호출 비용 비교. 10분 경계, 끊김, 순서 역전, 타 사용자 배정 접근을 검증.
6. 로컬 시연 및 미해결 위험 보고 후 사용자 배포 명령을 기다린다.

구현 전 추가로 정할 세부사항: Live Call 외 기능의 비노출/제거 범위, 로컬 기록 보관 범위, 공급자 키의 운영 소유 방식. 이번 보고서는 이 항목을 확정한 구현 스펙이 아니다.
