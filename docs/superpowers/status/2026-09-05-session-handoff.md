# NOVA 전체 작업 인계 — 2026-09-05

이 문서는 다른 세션이 대화 전체를 다시 읽지 않고 작업을 이어가기 위한 인계본이다. 사용자의 확정 요구, 단계별 구현, 검증 근거, 미완료 사항을 구분한다. 문서 작성 자체를 위해 제품 코드 수정·전체 테스트 재실행·배포는 하지 않았다. 아래 테스트 수치는 직전 구현 작업의 최종 보고와 기존 문서를 대조한 결과다.

## 1. 바로 알아야 할 현재 상태

- 작업 대상은 **NOVA**이며 핵심 메뉴는 **캡션 / Live Call / 설정**이다. Canvas는 별도 프로젝트와 Git 저장소로 분리했다.
- 사용자 승인에 따라 디자인과 기능을 로컬 구현해 왔다. 최근 작업은 **버튼 규격 통일 → 역할별 분석 → 언어 감지 표시 안정화와 요약 대기 개선**이다.
- 기본 엔진은 **Soniox 인식 + 자체 번역**이다. 선택 엔진은 **Gemini Live Transcribe → Flash 텍스트 번역**이다. Soniox 캡션 경로에 Flash를 끼우지 않는다.
- 공급자 연결이 끝나도 제품 회의는 계속 유지한다. **호스트의 명시적 종료가 회의 종료**다. 엔진 배정 변경은 다음 세션에 적용한다.
- 최근 최종 회귀 결과는 **루트 1,511 + gateway 625 + 웹 1,107 = 3,243 통과**, 루트 19개 건너뜀, 실패 0이다. 실제 유료 모델·운영 DB·다중 물리 기기 검증 완료를 뜻하지 않는다.
- 실제 배포, 최신 DB 마이그레이션 적용, 최종 Electron 패키징은 완료로 보고하면 안 된다. 사용자도 현재 전체 빌드까지는 필요하지 않다고 했다.
- 현재 브라우저의 `3322`는 실제 데스크톱 렌더러에 **모의 IPC**를 연결한 시연이다. 실제 음성 송출이나 계정·DB 통합 환경이 아니다.
- **라이선스 강제 검사, 요약 이메일 실제 발송, 지속 요약 작업 큐, Drive 문서 가져오기, 웹 토큰 결제는 미완료**다.

## 3. 사용자가 확정한 제품 정책

### 3.1 핵심 기능과 엔진

1. 캡션, Live Call, 설정에 집중한다. 회의 기록은 Live Call 내부, 용어집은 설정 흐름으로 구성한다.
2. ‘오프라인 캡션’은 인터넷 기반 인식·번역 결과를 PC에 표시하는 뜻이다. 완전 오프라인 모델 실행 요구가 아니다.
3. 가입자의 기본 엔진은 Soniox이며 최대 **3개 출력 언어**를 유지한다. 언어는 검색해서 다중 선택한다.
4. 관리자가 사용자에게 엔진을 배정한다. 실행 중 세션은 시작할 때의 엔진과 설정 revision을 유지하고 다음 세션부터 새 배정을 적용한다.
5. Soniox는 인식과 번역을 직접 담당한다. Flash는 Gemini 전사 후 번역이나 종료 요약 등 필요한 경로에서 사용한다.
6. 연결 시간 한도나 일시 단절 시 호스트가 종료하지 않았다면 복구한다. 종료 후 늦은 응답이 새 연결이나 회의를 되살려서는 안 된다.
7. 입력 감지 언어와 사용자가 읽는 출력 언어를 분리한다. 한국어 문장 안의 영문 약어 때문에 번역 방향과 표시 위치가 바뀌면 안 된다.

### 3.2 역할

| 역할 | 사용자가 원하는 책임 | 현재 상태와 후속 과제 |
| --- | --- | --- |
| 운영자·개발사 | 호스트 기능 전체와 별도 회원·라이선스·엔진·사용량 관리 | 기존 `/console/users`, `/console/engine`, `/console/sessions` 존재. 타 고객 회의 전체 열람과 정식 라이선스 정책은 별도 구현 필요 |
| 호스트 | 라이선스를 받아 회의 준비·캡션·Live Call·설정·기록 운영 | 자신의 회의 소유권을 검사하는 흐름. 계정 승인과 유효한 유료 라이선스는 동일하지 않음 |
| 참여자 | 일회성 입장, 대기, 번역 열람, 허용된 발언 요청, 종료 원문·요약 | 제품 회원가입과 분리된 회의별 참여 권한 사용 |

역할, 계정 승인·정지 상태, 라이선스, 회의별 참여 권한을 별도 개념으로 유지한다. 운영자의 전 고객 지원 접근은 사용자 요구로 남아 있지만, 현재 admin이라는 이유만으로 모든 소유권 검사를 우회하도록 만들지 않았다. 후속 제안은 지원 대상 선택과 감사 기록을 가진 별도 지원 모드다.

### 3.3 로그인과 비밀 설정

- 호스트는 일반 가입 또는 Google 가입을 사용한다. 사용자 요청 관리자 식별자는 `noel`이다.
- 관리자 비밀번호·해시·API 키·입장 토큰은 이 문서에 수록하지 않는다. 대화에 제공됐던 비밀번호도 코드, 주석, 문서에 다시 쓰지 않는다.
- 관리자 구성은 기존 `scripts/configure-admin-login.mjs`와 운영자 설정 문서를 따른다. 실제 관리자 이메일은 별도 설정이 필요하다.
- 개인 API 키는 **기기 저장**을 사용한다는 결정이다. 계정에 원문 키를 올리거나 운영자가 조회하는 흐름이 아니다. OS 보안 저장과 사용 경로의 완성 여부는 추가 검증해야 한다.
- 웹만 사용하는 경우 토큰 구매 방식으로 운영하고 싶다는 요구가 있다. 결제와 사용량 차감은 아직 구현 완료가 아니다.

### 3.4 참여자 입장과 종료

- QR 초대 주소에는 입장 권한이 포함되어 코드 입력을 생략한다. 간략 정보와 동의 절차까지 생략하는 것은 아니다.
- 일반 입장 주소는 인증코드로 입장한다. 현재 `#code=` 포함 공유 링크는 코드를 미리 채우므로 일반 주소와 편의 공유 정책을 분명히 해야 한다.
- `#invite`는 서버에서 회의 권한으로 교환하는 초대 토큰이다. ‘스캔 여부’를 신뢰하는 방식이 아니다.
- 예정 시각까지 대기하고 실제 호스트 시작 신호로 라이브 화면에 진입한다. 카운트다운만으로 송출을 시작하지 않는다.
- 사용자 희망은 최소 정보 입력과 요약 수신 동의다. 현재는 이름·이메일이 필수이고 회사·부서·직책은 선택 정보다. **이름 필수 / 이메일은 요약 수신 시 필수**로 바꾸는 것은 제안 단계다.
- 요약 이메일 동의와 개인정보 안내를 구분한다. 현재는 요약 수신 신청 저장까지이며 실제 메일 발송은 없다.
- 종료 후 원문과 요약을 볼 수 있어야 한다. 현재 종료 기록 접근 기한은 6시간이며 안내·보존·메일 정책을 함께 정리해야 한다.
- 예약 QR은 세션 만료 정책에 연결된다. 일정 변경 후 이미 인쇄한 QR의 지속성은 추가 회귀 검증 대상이다. 영구 QR라고 안내하지 않는다.

### 3.5 화면·컨트롤러·발언자

- 시스템 언어와 자막 언어를 분리하고 한국어, English, 日本語처럼 자국어 이름을 표시한다.
- 참여자 모바일 화면은 넓은 번역 본문과 발언자 사진·이름 중심의 어닝콜 형태다. 공유는 우측 메뉴, 전체 UI 언어는 지구본으로 제공한다.
- 데스크톱 컨트롤러는 내부/메인 화면을 우선한다. 자막은 메인, 확장, 양쪽 또는 표시 안 함을 선택한다.
- 자막 위치·글자 크기·배경 투명도를 실행 중 변경한다. 설정 변경 때문에 녹음이나 송출을 다시 시작하지 않는다.
- Live Call은 웹 출력과 선택적 로컬 자막을 함께 지원한다.
- 같은 호스트 계정의 태블릿·노트북 웹앱은 동일 회의 QR과 진행 화면만 표시한다. 마이크 송출을 넘겨받지 않는다.
- 발언자는 사진·이름·회사·부서를 사전 등록한다. 현장은 호스트 수동 선택을 기준으로 하며 음성·얼굴 자동 식별은 하지 않는다.
- 온라인 참여자와 등록 발언자 연결은 명시적으로 한다. 이름이 같다는 이유로 연결하지 않는다.
- 온라인 발언권자가 연결된 프로필을 사용하고, 연결되지 않았다면 본인의 입장 이름을 사용한다. 현장 선택 프로필을 잘못 빌려 쓰면 안 된다.
- 과거 발언은 당시 프로필 스냅샷을 유지한다. 명단 수정으로 이전 원문·번역·요약의 발언자 이름이 바뀌면 안 된다.

### 3.6 용어집

PDF·Google Drive 문서에서 전문 용어·고유명사를 추천하고 **사용자 확인 후 중복·충돌 없이 선택 등록**한다. 자동 무검수 등록은 선택하지 않았다. 오디오 전사용 Transcribe Live를 문서 분석 엔진으로 사용하지 않는다. 문서 처리 모델과 전사 모델을 분리한다. PDF 후보 검수 관련 일부 개선은 구현했지만 Drive OAuth·문서 가져오기 전체는 미완료다.

## 5. 구현 상세와 유지해야 할 계약

### 5.1 엔진과 연결 수명

- Soniox 다중 출력은 대상 언어별 경로로 처리하며 원문 기록을 중복 생성하지 않도록 구성했다. 연결 복구도 대상 경로별로 처리한다.
- 데스크톱 관리형 캡션은 서버가 승인 계정과 세션을 확인한 후 제한된 공급자 자격 증명을 발급한다. 종료된 `managed_caption_sessions`에서 새 티켓이 발급되어서는 안 된다.
- 새 엔진 배정이 재연결 시 실행 중 세션을 바꾸지 않도록 시작 당시 엔진과 revision을 고정한다.
- 자동 입력 감지에서는 출력 언어 목록을 입력 언어 제한으로 잘못 취급하지 않는다.
- 호스트 종료 뒤 도착한 시작 응답, 취소된 연결의 콜백, 이전 provider generation의 결과를 무효화한다.
- Gemini의 임시 전사와 확정 전사를 구분하며 잘리거나 부분적인 응답을 완전한 최종 원문으로 저장하지 않는다.

### 5.2 입력 언어 안정화 — 가장 중요한 최근 변경

실시간 공급자는 문맥이 늘면서 중간 언어 태그를 수정할 수 있다. 기존 언어 합의 로직이 있어도 실제 캡션 경로와 연결되지 않은 부분이 있었다. 데스크톱과 gateway를 각각 수정했다.

1. 충분히 확인된 단일 언어의 임시 표시 경로를 현재 구간 동안 유지한다.
2. 그 경로와 상충하는 중간 결과는 다른 언어 칸으로 옮기지 않고 보류한다.
3. 짧고 애매한 약어만 있을 때는 성급하게 언어를 고정하지 않는다.
4. 확정 본문은 다시 검증한다. 혼합·미확정 원문에 거짓 단일 언어를 붙이지 않는다.
5. 구간 확정, 발언자 변경, 재연결, 정지 시 적절히 초기화한다.
6. `segmentId`와 generation을 사용해 이전 구간의 늦은 final이 새 구간 잠금을 풀지 못하게 한다.
7. 데스크톱의 마이크·시스템 음원 상태를 분리하고 늦은 비동기 번역의 덮어쓰기를 막는다.

**보장 범위는 공급자가 확정한 발화 구간이다.** 이는 항상 문법적인 한 문장과 같지 않다. 긴 문장 중간에 공급자가 구간을 확정할 수 있다. ‘모든 문장 끝까지 100% 언어 고정’ 또는 ‘인식 정확도 100%’로 보고하면 안 된다. 초기 애매한 음성은 표시가 잠시 늦어질 수 있다. 이번에 endpoint 지연 설정을 무작정 낮추지는 않았다.

공식 근거는 2026-09-05 작업에서 확인했다. 새 세션에서 모델 API를 변경할 때는 최신 문서를 다시 확인한다.

- [Soniox 언어 감지](https://soniox.com/docs/stt/concepts/language-identification)
- [Soniox endpoint](https://soniox.com/docs/stt/rt/endpoint-detection)
- [Gemini Live Transcribe](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe)

### 5.3 요약 대기와 원문

- 원문과 요약을 함께 기다리던 흐름을 분리해 먼저 도착한 원문을 보여준다.
- 참여자 종료 화면 기본 탭은 원문이며 AI 요약은 생성 중 skeleton을 표시한다.
- 서버의 정상 `pending/running`은 횟수 초과만으로 생성 실패로 바꾸지 않는다. 최대 25초 간격으로 상태 확인을 이어간다.
- 네트워크 조회 실패와 실제 서버 생성 실패를 구분한다. 연속 조회 실패는 제한하고 재확인 경로를 제공한다. 실제 생성 실패를 무한 로딩으로 숨기지 않는다.
- 숨겨진 페이지에서는 조회를 쉬고 종료·언어 변경 시 타이머와 요청을 정리한다. 진행 중 요청과 중복 자동 조회를 막는다.
- 기록 화면도 생성 중 상태를 25초 간격으로 확인한다. 이전 언어의 타이머가 새 언어 선택을 되돌리는 경합을 마지막 검수에서 수정했다.
- 요약의 발언자 귀속은 당시 프로필을 사용한다. 현재 참여자 이름·소속으로 과거 발언을 덮어쓰지 않는다.

서버에는 여전히 조회 5초, 모델 시도당 20초, 전체 60초, DB lease 5분과 종료 후 `after()` 실행 구조가 있다. 지속 큐·worker·heartbeat가 없으므로 장시간 작업 보장까지 해결한 것은 아니다. 실제 공급자 timeout 해결은 별도 후속 작업이다.

### 5.4 발언자 명단과 이력

공통 프로필 필드는 `id`, `version`, `displayName`, `company`, `department`, `photoAssetId`다. 명단은 `sessionId`, `revision`, `appliedRevision`, `activeOnsiteSpeakerId`, `speakers`를 가진다. 온라인 연결에는 `participantId`를 사용한다. 수정 요청은 `expectedRevision`으로 충돌을 검사한다.

- 최대 30명, 이름 1–40자, 회사·부서 각 80자 이하 정책이다.
- 사진은 최대 2MiB JPEG/PNG/WebP 입력을 검증하고 sharp로 메타데이터를 제거한 WebP로 변환한다. 결과 크기 제한은 256KiB다.
- 사진은 임의 외부 URL이 아니라 권한이 확인된 자산 경로를 사용한다.
- 수정 revision과 실제 오디오 적용 acknowledgment를 구분한다.
- PCM 구간과 발언자 스냅샷을 연결해 명단 변경 직후 이전 오디오가 새 발언자 이름을 받는 문제를 막는다.
- 귀속이 불명확한 발언은 확인 필요/화자 미상으로 표시하며 임의로 Host 또는 현장 발언자를 지정하지 않는다.

### 5.5 공통 버튼·도움말·캡션 준비

`DESIGN.md`의 최신 통합 컨트롤 정책을 우선한다. 일반 버튼과 입력은 44px, 기본 버튼 radius는 8px, 짧은 단어 중심의 한 줄 레이블을 사용한다. 긴 설명은 오른쪽 별도 `?` 도움말로 제공한다. 위험한 종료 결과나 오류 설명까지 도움말 안에 숨기지 않는다.

도움말은 클릭·터치·키보드, Escape, 바깥 클릭을 지원하고 화면 경계를 넘지 않도록 한다. Escape가 상위 모달까지 닫는 문제, 도움말 관찰자의 자기 반복, 분리된 요소 잔류를 수정했다. range·checkbox 도형·textarea·내용형 발언자 행을 모두 44px로 강제하지 않는다.

캡션 준비는 언어·출력 화면·시작 중심이다. 용어집·표시 상세는 접어 두고 기존 DOM ID와 설정 값을 유지했다. 출력 화면 목록의 늦은 응답이 최신 선택을 덮거나 체크박스 재생성이 키보드 초점을 잃게 하던 문제를 수정했다.

### 5.6 호스트 보조 웹 화면

같은 계정으로 `/host-screen`에서 자신의 회의를 선택하고 `/stage/[id]`에서 QR과 진행 화면을 본다. 조회 완료 후 주기적으로 갱신하며 인증·소유권 오류 시 사적인 상태를 지운다. 보조 화면은 입장 권한을 임의 재발급하거나 회의를 시작하지 않는다. 화면을 닫아도 송출 세션이 끝나지 않는다.

보조 화면 QR의 서버 확인 코드 hash 경로와 참여자 `#invite` 교환 경로를 동일한 것으로 단정하지 않는다. 실제 기기 간 접속에는 동일한 배포 환경과 HTTPS 주소가 필요하다. 태블릿의 localhost는 개발 노트북이 아니다.
