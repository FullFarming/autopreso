# NOVA 핵심 제품 구현 및 검증 보고

2026-09-05. 로컬 구현·통합 검증 보고. 배포와 운영 DB 적용은 수행하지 않았다. 변경사항은 작업 트리에 있으며 커밋하지 않았다. 기존 다른 세션의 미추적 파일은 보존했다.

## 구현 결과

- 사용자 기능 탐색을 캡션 / Live Call / 설정으로 정리했다. 웹은 Live Call과 설정, PC는 세 기능을 제공한다. 기록·요약은 Live Call 아래, 용어집과 관리자 콘솔 진입은 설정에 배치했다.
- 신규 사용자 기본값은 Soniox 인식 + Soniox 자체 번역이다. Soniox 자막 실행에서 Gemini 키·SDK·실시간 주제 추론 의존성을 제거했다.
- 관리자 사용자 목록에서 Soniox 또는 Gemini를 배정한다. Gemini는 `gemini-3.5-transcribe-live` → Flash 텍스트 번역이다. 기존 세션의 엔진과 배정 버전은 재연결 중에도 유지한다.
- 출력 언어는 선택한 최대 3개를 유지한다. 선택된 언어가 발화 원문 언어이면 원문을 표시하고 다른 언어만 번역한다. 자동 인식에서 출력 언어로 입력 언어를 강제로 제한하지 않는다.
- Soniox 3개 언어는 대상별 별도 연결을 사용한다. 게이트웨이는 원문을 한 번 기록하고 언어별 연결을 독립적으로 복구한다. 다른 발언의 번역을 잘못 연결하지 않도록 원문·음성 시간 범위를 검증한다.
- 공급자 연결 수명과 제품 세션 수명을 분리했다. Gemini 연결의 선제 교체·goAway·무음 상태·마지막 PCM 조각을 처리한다. 호스트 종료 후 연결·대기 작업·늦은 결과를 차단한다.
- Live Call 접근과 입장권을 주기적으로 갱신한다. 호스트가 현재 열어 둔 입장 기간만 연장하며, 중지·만료·철회된 초대를 자동으로 다시 열지 않는다.
- 용어집의 모든 대상 언어를 편집·검색·저장한다. 번역 금지 항목의 빈 번역을 정상 저장하고, 기존 별칭·맥락·메타데이터는 보존한다.

## 회원가입과 관리자

기존 이메일/Google 가입을 유지하며, 사용자 API 키 입력을 요구하던 캡션 시작 검사를 제거했다. 서버가 승인된 사용자의 배정과 세션 상태를 확인한 뒤 임시 연결 권한을 발급한다. 영구 모델 키는 서버에 둔다.

`noel` 비밀번호를 검증한 후, 설정한 실제 이메일의 Supabase 사용자·관리자 프로필을 연결한다. 사용자 이름만으로 권한을 부여하지 않는다. 잘못된 비밀번호·설정 누락·차단 계정·권한 충돌은 명시적으로 거부한다.

요청한 비밀번호는 scrypt 해시로 로컬 비공개 설정에 저장했다. 실제 관리자 이메일인 `ADMIN_BOOTSTRAP_EMAILS`는 사용자 설정이 필요하다. 운영 계정 생성·Google 동의·실제 메일 발송을 검증했다고 주장하지 않는다.

## 아키텍처 결정

| 경계 | 결정 및 이유 |
|---|---|

| PC 자막 인증 | 서명 티켓과 서버 `managed_caption_sessions`를 함께 확인. 서명만 확인하면 종료된 세션의 티켓을 재사용할 수 있어 서버 종료 상태가 필요 |
| PC 음성 경로 | Soniox 임시 키 또는 Gemini constrained 단기 토큰으로 직접 STT 연결. Gemini Flash 번역은 인증된 서버 요청으로 수행 |
| 캡션 메타데이터 | 서버에는 소유자·엔진·배정 버전·언어·접근 만료·종료 상태만 보관. 이 신규 테이블에 음성이나 자막 본문은 저장하지 않음 |
| 만료 복구 | 키 발급·번역에는 현재 유효한 티켓 필요. 긴 절전 후 갱신은 현재 승인된 소유자 인증과 서버의 활성 세션을 확인해 동일 배정으로 복구 |
| 용어집 | 세션 중 고정된 용어를 인식 힌트·번역 대응표·결정적 교정에 사용. Soniox 뒤에 Flash 교정을 붙이지 않음 |
| 기존 기능 | 미사용 기능의 제품 진입을 줄였다. 과거 데이터와 다른 세션의 파일을 일괄 삭제하지 않음 |

초기 연구에서 SDK의 languageCodes 변환기 제약을 gateway STT 장애로 추정했으나 실제 gateway는 이미 raw WebSocket을 사용했다. 호출 경로 재검증 후 해당 분석을 정정하고 불필요한 SDK 변경을 제외했다.

## 적대적 검토에서 발견하고 수정한 문제

1. 서버 서명만 있는 캡션 티켓은 호스트 종료 후 재사용 가능했다. 서버의 활성/종료 상태와 현재 승인된 소유자를 검증하도록 변경했다.
2. 승인 캐시가 저장소 장애 시 만료된 승인 정보를 계속 허용했다. 유효기간이 지난 캐시로 권한을 승인하지 않도록 수정했다.
3. Gemini 임시 토큰이 일반 WebSocket 경로를 사용했고 언어 제약이 실제 설정과 달랐다. constrained 경로와 동일한 자동 인식·용어 설정을 사용하도록 수정했다.
4. Soniox 9분 연결 교체 간격과 1분 전 인증 갱신 조건 때문에 6시간 경계를 놓칠 수 있었다. 갱신 여유를 15분으로 늘리고 369분 시뮬레이션으로 검증했다.
5. 캡션 시작 권한 발급 중 호스트가 정지하면 서버 메타데이터가 남았다. 시작 소유권을 잃은 요청의 새 서버 세션을 폐기한다.
6. 참가자 접근 갱신 endpoint가 호스트 전용 middleware에 막혔다. 참가자 경로로 분류하되 서명 입장권·정확한 Origin 검증을 유지했다.
7. UI가 Soniox와 관리형 사용자도 로컬 Gemini 키 없이는 시작하지 못하게 했다. 서버의 배정·키 발급 검증으로 통일했다.
8. 잘린 Gemini 응답을 정상 번역으로 처리할 수 있었다. 정상 완료 응답만 확정 번역으로 허용했다.
9. 콘솔 API 파일의 일반 helper export가 Next.js 배포 빌드를 막았다. helper를 서버 라이브러리로 옮겼다.
10. 선택한 언어에 한국어·영어를 추가해 세 언어를 초과시키는 경로를 제거했다. 기본값과 명시적 사용자 선택을 분리했다.

## 남은 운영 확인

- 실제 관리자 이메일, Vercel/Supabase/Google OAuth 및 모델 키 설정, 두 migration 적용, 새 PC 설치본 배포가 필요하다.
- Soniox 3개 언어는 입력당 3개 동시 스트림, 동시 연결 교체 중 최대 6개가 될 수 있다. 두 입력 장치를 동시에 사용하면 그만큼 한도가 더 필요하다.
- 독립 Soniox 전사의 경계가 달라지면 해당 번역을 누락 상태로 표시할 수 있다. 잘못된 발언에 붙이지 않는 것을 우선했고 실제 음성으로 언어별 누락률·지연을 측정해야 한다.
- Soniox의 중국어 wire 코드는 `zh`이며 간체/번체 출력의 정확한 구분은 실제 품질 검증이 필요하다. 코드 라벨 대응만으로 번체 품질을 보장하지 않는다.
- Gemini 단기 연결은 최신 공식 문서의 v1beta 계약을 따랐다. 실제 계정의 모델 접근 권한·constrained 연결 성공은 배포 전 실제 시험으로 확인한다.
- 긴 네트워크 단절의 음성을 무손실로 복구한다고 보장하지 않는다. 논리 세션을 유지하는 것과 장애 중 모든 음성을 복원하는 것은 별개다.
- 운영 반영 절차와 설정값은 [운영 설정 안내](2026-09-05-operator-setup.md)에 있다. 운영 배포는 별도의 명시적 지시 후 진행한다.
