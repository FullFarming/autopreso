# 요약·원문 이메일 수신과 호스트 기록 / Excel 설계

날짜: 2026-08-31 (한국시간)

최신 실행 결과: [구현·검증 보고서](2026-08-31-live-recap-implementation-report.md). 아래의 최초 조사/미구현 표는 설계 당시 이력이며 현재 상태는 최신 보고서를 따른다.

상태: 사용자가 구현을 승인하여 로컬 구현·검증 중이다. 실제 이메일 발송은 사용자가 별도로 처리하며 이번 구현에서 제외한다. 외부 DB·클라우드 배포는 실행하지 않았다. 이미지와 로컬 시연의 인물·이메일·수치는 예시 데이터다.

최신 확정: 하단 `웹 열람은 종료 후 ~ 별도 보관` 문구만 삭제한다. 웹 열람 6시간과 새로고침 복구 정책은 유지한다. 아래 최초 설계 중 주소 검증·발송 작업·배달 상태는 향후 별도 발송 시스템의 참고 계약이며 이번 구현 완료 항목이 아니다. 현재 서버와 UI는 수신 신청/취소만 기록하고 발송 완료를 표시하지 않는다.

관련 기본안: [라이브 화면·6시간 복구·게이트웨이 설계](2026-08-31-participant-demand-live-viewer-design.md). 사용자의 전체 구현 승인에 따라 수요 기반 휴면과 기록 공백 표시를 구현한다. 운영 활성화는 기본 꺼짐인 플래그와 별도 배포 승인으로 통제한다.

## 1. 범위와 확정 화면

사용자는 마이크 캡슐 형태를 확정했다. 라이브 중 요약받기는 없고, 마이크 허용 시 텍스트 없이 아이콘만 표시한다. 이번 확장은 회의 종료 후의 이메일 수신과 호스트 기록 관리다.

- [참여자 이메일 동의 시안](assets/2026-08-31-live-viewer-approved-no-footer.png)
- [호스트 기록·내보내기 시안](assets/2026-08-31-host-records-export.png)
- [생성 프롬프트와 방식](assets/2026-08-31-email-records-prompts.txt)

'전체 Excel'은 **선택한 한 회의의 전체 기록**으로 정의한다. 검색어, 현재 탭, 화면 페이지와 무관하게 그 회의의 전체 참여자·수신 신청자와 원문·요약을 내보낸다. 호스트의 모든 회의 일괄 추출은 이번 범위가 아니다.

참여자 웹 열람은 실제 endedAt부터 6시간이다. 호스트 기록은 기존 소유권·보존·삭제 정책을 따른다. 사용자 요청에 따라 별도 보관 안내 문구는 화면에 표시하지 않는다. 내려받은 파일은 웹 접근 만료와 별개다.

## 2. 참여자 버튼: 클릭 전에 보이는 동의

아래 표의 발송 관련 행은 **향후 별도 범위**다. 현재 구현은 미신청 → 요청 중 → 신청 완료/실패 및 취소 상태만 다룬다.

버튼 위에 아래 정보를 읽을 수 있게 제공한다. 숨겨진 약관이나 클릭 후 알림만으로 동의를 설명하지 않는다.

> 받을 이메일: 해당 참가자의 등록 주소
>
> 버튼을 누르면 이 회의의 요약·원문 이메일 수신에 동의해요.
>
> 마케팅 수신 동의는 포함되지 않아요.

버튼 이름은 기존 `요약·원문 받기`를 유지한다. 별도 체크박스로 중복 확인시키지 않되 고지와 수신 주소를 버튼에 접근성 설명으로 연결한다. 서버가 허용한 최신 고지 버전의 동의와 수신 신청을 클릭 시 함께 저장한다.

| 상태 | 참가자 표시·동작 |
|---|---|
| 미신청 | 위 안내와 활성 버튼. 단순 페이지 열람은 동의가 아님 |
| 요청 중 | 중복 클릭 방지, 처리 중 상태를 보조 기술에 알림 |
| 저장 성공 | `이메일 수신 신청이 완료됐어요`; 즉시 발송 성공으로 표시하지 않음 |
| 이메일 미검증 | 신청은 보존하고 `이메일 확인이 필요해요`. 원문 없는 확인 절차를 먼저 제공 |
| 원문·요약 준비 중 | `자료를 준비하고 있어요`; 새로고침으로 작업을 다시 생성하지 않음 |
| 발송 공급자 수락 | `발송 완료`는 서비스의 발송 완료이며 실제 수신함 도착을 보장하지 않음 |
| 배달 확인·반송 | 공급자 이벤트가 있을 때 별도 기록. 발송 수락과 혼동하지 않음 |
| 실패 또는 결과 불명 | 명확한 상태·재확인 제공. 저장 실패를 신청 완료로, 타임아웃을 성공으로 표시하지 않음 |
| 신청 취소 | 미발송 요청 중단. 이미 발송된 파일의 회수 가능성을 약속하지 않음 |
| 웹 접근 기한 경과 | 새 신청·다운로드 거절. 이미 접수된 요청의 상태는 서버 정책으로 처리 |

등록 이메일의 형식 검증만으로 소유 확인이 되지 않는다. 미검증 주소에는 회의 내용 없이 주소 확인용 메시지만 보낼 수 있도록 별도 검증을 둔다. 참가자가 주소를 수정하면 새 주소 소유 확인 후 현재 신청과 연결하고, 옛 주소로 대기 중인 발송은 무효화한다. 인증된 계정 주소라면 기존 검증 증거를 재사용할 수 있다. 이메일 발송 공급자 선정·설정은 실제 구현 단계에서 확정한다.

확인 토큰은 신청 ID·참가자 ID·정규화된 주소·주소 세대에 묶인 짧은 수명의 일회용 challenge다. 만료·다른 신청·이전 주소 세대의 재사용을 거부한다. 확인 메시지에도 참가자·회의·IP·주소별 요청 제한을 적용하고, 링크에 회의 내용이나 원문 열람용 bearer token을 넣지 않는다.

동의 목적은 해당 회의의 원문·요약 수신이다. 마케팅, 정기 구독, 다른 회의 수신으로 확대하지 않는다. 기존 요약 전용 v1 동의를 원문 포함 동의로 소급 변환하지 않는다. 이 문서는 법률 적합성 검토 결과를 주장하지 않는다.

## 3. 호스트 기록 흐름

기존 `라이브콜 기록` 진입점 → 회의 목록 → 특정 회의 상세를 유지한다. 상세 상단에는 목록 복귀, 회의명·종료 시각, `전체 Excel 내보내기`를 둔다.

| 탭 | 내용 |
|---|---|
| 참여자 | 이름, 이메일, 소속, 첫 입장 시각, 수신 신청 여부. 연결 수나 다중 탭 수를 인원으로 세지 않음 |
| 원문 | 권위 있는 발언 원문, 화자, 시각, 주제. 전체 페이지 조회, 언어별 번역은 내부 선택 |
| AI 요약 | 핵심 내용·주제별 요약, 생성 시각·언어·버전. 준비/실패/자료 없음 구분 |
| 수신 신청자 | 이름, 이메일, 소속, 신청 시각, 고지 버전·동의 시각, 주소 확인·발송 상태 |

시안에서는 수신 신청자 탭을 선택한 예시를 보여준다. 탭의 기능과 키보드 이동을 구현한 것은 아니다. 신청자의 상세 증빙은 행 펼침으로 확인하고 표에는 핵심 정보만 표시한다. 개인정보·운영 설정·삭제 UI를 기록 본문에 반복해서 배치하지 않는다.

수신 신청자는 새 목적의 신청을 실제로 기록한 사람이다. 입장 시 요약 수신 동의를 했다는 이유만으로 새 원문 포함 신청 리스트에 넣지 않는다. 명단 기본값은 취소하지 않은 신청이며 취소 이력은 필터·감사 기록에서 확인한다. Excel에는 상태를 명시해 전체 신청 이력을 포함한다.

모바일은 기존 `/m/records`와 같은 데이터 계약을 사용한다. 네 탭은 가로 스크롤 가능하게 하고, 표의 행은 이름·이메일·신청 시각·상태를 담는 목록으로 바꾼다. 내보내기 버튼은 줄바꿈 배치해 320px에서도 화면 밖으로 밀리지 않게 한다. 이름 생략으로 신청자를 구분하지 못하게 만들지 않는다. 44px 이상 조작 영역, 키보드 focus, 탭 role/selected 상태를 유지한다.

## 5. 동의·신청·발송 계약 (발송 부분은 향후 범위)

1. 새 목적별 `POST /api/live-sessions/[id]/recap-request`를 제안한다. 참가자/회의 결합, Origin, 서버 endedAt+6시간, 최신 고지 버전, 요청 제한을 검증한다. live grant가 정리된 종료 회의도 별도 읽기 복구 인증·보존 membership으로 확인한다.
2. 입력은 서버가 발급/허용한 고지 버전과 멱등 요청 키 정도로 제한한다. 클라이언트의 임의 participantId, 수신 주소·CC/BCC, 마케팅 값을 신뢰하지 않는다.
3. 트랜잭션 안에서 목적별 동의 원장과 신청을 함께 기록한다. 새 `live_recap_requests`는 sessionId+participantId 단위 유일 요청, consentId/revision, requestedAt, cancelledAt, 상태를 보유한다. 결정 시각은 서버 값이며 단순 재클릭은 기존 시각·동의 이력을 재작성하지 않는다.
4. 별도 발송 작업은 requestId+명시적 자료 버전으로 중복을 막는다. 요약 생성 완료 전에 자료 버전을 먼저 고정하지 않는다. 자동 갱신된 새 요약 버전만으로 재발송하지 않는다. 최종 자료 스냅샷을 만들고 한 신청에 한 전달물을 연결한다.
5. 공급자 호출은 트랜잭션 밖에서 실행한다. 발송 직전에 동의 철회·이메일 주소 세대·주소 검증·호스트 공개/삭제 정책을 다시 검사한다. 경합 시 revision/원자적 claim으로 한 작업만 발송 권한을 얻는다.
6. 작업 상태는 주소 확인 필요 → 자료 준비 → 대기 → 발송 중 → 발송 수락/실패/결과 불명/취소로 구분한다. 공급자 메시지 ID와 멱등 키를 기록하고, 타임아웃은 상태 확인 없이 무조건 재발송하지 않는다.
7. 새로고침은 기존 신청/작업/요약 상태를 읽을 뿐 새로운 동의나 메일을 생성하지 않는다. 영구 저장은 서버에 두고 브라우저 저장소에 원문·참가자 명단·토큰을 저장하지 않는다.
8. 6시간 이내 접수된 유효 요청은 웹 열람 종료와 별개로 작업 완료가 가능하다. 하지만 주소 확인은 기존 허용 기간 안에 끝나야 하고, 이후에는 새 신청 또는 새 수신자로 변경할 수 없다. 실행 직전 취소·삭제·권한 철회는 계속 검사한다.
9. 이메일은 해당 참가자에게 공개된 요약과 발언 원문만 포함한다. 참가자 명단, 수신 신청자 목록, 내부 진단·토큰은 포함하지 않는다. 기본 전달물은 요약 문서와 UTF-8 원문 파일이며, 형식·용량 초과 처리는 구현 단계에서 검증한다. 큰 자료는 인증된 다운로드 방식으로 바꿀 경우 만료 정책을 명시한다. 공개 무기한 링크는 사용하지 않는다.

발송과 취소의 경계는 request·consent·address revision을 검증한 원자적 `sending` 전환이다. 그 전에 취소가 먼저 성공하면 발송하지 않는다. 전환 후 취소에는 `발송이 진행 중이라 취소를 보장할 수 없어요` 상태를 반환한다. 외부 송신까지 DB 트랜잭션에 넣어 원자적이라고 주장하지 않는다. 오래된 worker가 살아 있을 수 있으므로 lease 만료만으로 중복 송신을 허용하지 않으며 공급자 멱등 키를 동일하게 유지한다.

과거 행의 상태는 사실대로 `신청 없음` 또는 기존 요약 전용 동의로 둔다. 실제 메일 증거 없는 과거 행을 발송 완료로 채우지 않는다. 스키마는 additive migration으로 만들고 기존 enum/원장을 drop하지 않는다.

## 6. 전체 Excel 계약

호스트 소유권이 확인된 해당 회의 데이터만 한 개 `.xlsx`로 만든다. 페이지 크기나 UI 필터에 따라 누락되지 않게 서버의 기준 시각과 순번/버전으로 스냅샷을 고정한다.

이메일·동의·발송 상태는 변경 가능한 값이므로 시각과 자막 순번만으로 스냅샷을 구현하지 않는다. 동일 DB 스냅샷에서 필요한 행을 자료화하거나 해당 버전의 원장을 읽는다. 모든 시트와 총계를 같은 `exportSnapshotId`로 연결하며, 서로 다른 페이지의 최신 상태를 섞지 않는다.

| 시트 | 필드 |
|---|---|
| 회의 정보 | 회의명, 일정/실제 종료, 생성 시각·시간대, 각 시트 건수, 포함 범위, 기록 공백·요약 상태 |
| 참여자 | 참가자 ID, 이름, 이메일, 소속, 첫 입장 시각, 수신 신청 상태 |
| 원문 | 발언 ID·순번, 화자, 언어, 시각, 주제, 원문, 기록 공백 안내 |
| AI 요약 | 언어, 생성 버전·시각·상태, 주제/항목, 요약 내용 |
| 수신 신청자 | 참가자 ID, 이름·이메일·소속, 신청 시각, 동의 고지 버전·시각, 취소/주소 확인/발송 상태·시각 |

- 호스트별 접근 통제, 다운로드 요청 제한, 내보내기 감사 기록과 `private, no-store`를 적용한다. 참가자 인증으로 명단·건수·파일에 접근할 수 없다.
- 모든 사용자/AI 텍스트를 수식이 아닌 문자열 셀로 쓴다. 자동 hyperlink, 수식, 외부 연결, 매크로를 생성하지 않는다. `= + - @` 및 선행 공백·탭 공격을 테스트한다. CSV 확장자만 바꾼 파일은 금지한다.
- 긴 원문은 명시적인 연속 행/분할 구조로 유지하고, 용량 초과 시 실패나 별도 파일 분할을 안내한다. 조용히 자르거나 일부 페이지를 전체라고 내보내지 않는다.
- 언어별 원문 중복을 피한다. 진짜 원문이 없는 행을 번역문으로 메우지 않는다. authoritative transcript와 사용자 공개 DTO를 사용하며 provider 내부 payload는 제외한다.
- 검색 중에도 버튼은 `이 회의 전체` 범위를 표시한다. 총계는 파일 생성의 같은 기준 시점으로 계산한다.
- 요약 생성 중·실패·미수집 구간은 상태/범위를 시트에 기록한다. 빈 요약을 성공으로 표시하거나 전체 회의가 기록됐다고 추정하지 않는다.
- Excel은 민감정보가 포함된 다운로드임을 생성 전에 알린다. 호스트가 다운로드한 뒤의 보관·재공유를 서비스가 자동 회수할 수 있다고 주장하지 않는다.

## 7. 구현 경계·위험·검증

| 담당 | 파일 소유 경계 |
|---|---|
| Design | `webapp/components/live/records/`, 참가자 종료 CTA·동의 표시. 실제 UI 수정은 필수 Design 담당 |
| Schema | 목적별 동의 재사용 RPC, 신청·발송 작업·감사 테이블의 additive migration |
| Backend | recap-request/상태 API, live-records recipients/export와 XLSX 생성 |
| Security | 인증 scope, 목적 분리, Origin·rate limit, 주소 검증, 파일 안전성 검토 |
| Delivery | 발송 worker/adapter, 자료 스냅샷, 공급자 결과 추적. DB 트랜잭션에서 외부 송신 금지 |

중요 위험은 타인 주소로 자료 전송, 마케팅 선택 덮어쓰기, 중복 발송, 권한 없는 명단 내보내기, 전체 행 누락, 웹 6시간과 첨부 보관의 혼동이다. 위 계약으로 방어하며 실제 공급자·파일 생성·모바일 검증은 구현 단계에 남아 있다.

| 적대적 시나리오 | 수락 기준 | 현재 결과 |
|---|---|---|
| A1 두 탭 동시 클릭·타임아웃 | 요청·발송 각 1건, 기존 동의시각·마케팅 보존 | 설계 검토, 미구현 |
| A2 다른 호스트/참가자로 명단·export 접근 | 403/404, 건수·파일 유출 없음 | 기존 소유권 정적 확인, 신규 검증 대기 |
| A3 유사/누락 Origin | 변경 요청 거절 | 계약 정의 |
| A4 악성 이름/AI HTML·수식 | 화면 코드 실행·Excel 수식 실행 없음 | 계약 정의 |
| A5 임의 첨부 URL/수신자 주입 | 서버 대상·자료만 사용 | 계약 정의 |
| A6 6시간 경계·한글·긴 셀·대용량 | 경계 정확, 누락/조용한 절단 없음 | 테스트 명세 |
| A7 철회·주소 변경·작업 중 삭제 | 미발송 중단, 이미 발송된 파일 회수 약속 없음 | 테스트 명세 |
| A8 모바일·200% 확대·키보드 | 고지와 주소를 클릭 전 읽을 수 있고 탭·export 사용 가능 | 정적 이미지 확인, 기능 시연 전 |

최초 시안 검토 이후 사용자가 구현을 승인했다. 현재 API·XLSX·화면은 로컬 구현했으며 최신 실행 결과는 별도 구현 검증 보고서와 design-qa.md를 따른다. 메일 발송은 구현 범위가 아니다. 배포는 명시적 승인 후에만 진행한다. 되돌릴 때 새 액션/worker를 중지하고 기존 기록 열람을 유지하며, 동의 원장·생성 자료는 파괴적으로 지우지 않는다.

최종 검토에서 이메일 확인 토큰 결합, 취소와 송신의 확정 경계, 변경 가능한 값의 Excel 스냅샷 조건을 보완했다. 시안에서는 누락됐던 새로고침 복구 안내를 상단 열람 기한에 복원했다. 미구현 기능의 PASS 보고가 아닌 설계 결함 보완이다.
