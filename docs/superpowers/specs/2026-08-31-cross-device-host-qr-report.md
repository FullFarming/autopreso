# 동일 호스트 계정의 다른 기기에서 참여 QR 확대

## 요구사항과 범위

- Electron에서 만든 대기 세션을 같은 호스트 계정으로 로그인한 웹/다른 기기에서 복원하고 참여 QR을 크게 표시한다.
- 기존 방송 장치의 마이크, 자동 시작, 게이트웨이 소유권을 바꾸지 않는다. 세션이 여러 개면 기존 선택 화면을 유지한다.
- QR 링크는 인증 코드를 채우기만 한다. 이름·이메일·필수 동의와 기존 입장 검증을 생략하지 않는다.
- 한국어·영어·일본어 시스템 언어를 따른다. DB 변경, 이메일 발송, AI 호출, 운영 배포, Electron 설치 파일 재패키징은 수행하지 않았다.

## 구조 및 결정

1. 기존 소유자 제한 세션 조회와 `read-if-open` 초대 조회를 사용한다. 기존 초대 토큰은 해시로 저장되므로 원래 토큰을 복원하거나 새 토큰을 발급하지 않는다.
2. 복원한 6자리 코드로 `/m/watch#code=001234` 형태의 링크를 만든다. 코드를 서버 URL query에 넣지 않는다. 기존 opaque invite 링크도 계속 지원한다.
3. 참여 화면은 최초 진입의 fragment를 엄격하게 검사한다. 중복 키·잘못된 코드·잘못된 invite는 거절하고, 잘못된 invite를 코드 인증으로 대체하지 않는다. 입력 후 hash 변경이 참여자 입력을 덮어쓰지 않는다.
4. `InviteQrDialog`는 유효한 현재 초대를 받아 로컬에서만 QR을 만든다. 1024px PNG, 4모듈 여백, 검정/흰색을 사용한다. portal + native dialog로 페이지 확대 배율과 독립적으로 표시하고 사용자가 원할 때 전체 화면으로 전환한다.
5. 만료·초대 교체·닫힌 입장 상태에서는 오래된 QR을 숨긴다. 전체 화면 실패 시 기존 확대 창을 유지하며 오류를 안내한다.
6. 검토 중 기존 만료 세션 복원이 조회만으로 TTL/version을 갱신하는 점을 발견했다. 일반 복원은 읽기만 하며, **입장 시간 연장 후 복원**을 명시적으로 누를 때만 기존 restore API를 호출하도록 수정했다.

## 실행 결과

- Node 24 웹 테스트: live 741개 + core 77개 통과.
- Node 24 루트 테스트: 1,356개 통과, 기존 4개 skip. 전체 실행 합계 2,174개 통과, 실패 0개.
- 타입 검사 및 `git diff --check` 통과. 별도 lint script는 이 프로젝트에 없다.
- 격리 디렉터리에서 Next 운영용 빌드 통과. 원본 개발 서버의 `.next`는 빌드로 덮어쓰지 않았다. 빌드 사본과 원본 소스 466개가 일치했다.
- 로컬 개발용 `ws:` 설정은 production CSP 검증에서 거절되었다. 격리 검증 프로세스에만 `wss://127.0.0.1:8787/live`를 지정해 재빌드·실행했다. 저장된 프로젝트 환경설정과 CSP를 수정하지 않았으며 이 주소로 실제 방송을 연결하지 않았다.
- 실제 빌드의 QR 링크를 브라우저에서 클릭한 후 화면 캡처로 `001234` 자동 입력을 확인했다. DOM 텍스트 조회에서는 해당 입력이 빈 값으로 보여 처음에는 불일치로 관측했으나 시각 검증과 실제 ReactDOM StrictMode 검사 모두 정상 입력을 확인했다. 도구의 값 숨김 여부는 추정이며 코드 원인으로 단정하지 않았다.
- 잘못된 QR 링크는 한국어 오류 안내와 비활성 참여 버튼을 표시했다. 정상 링크도 이름·이메일·필수 동의 전에는 참여하지 않는다.
- 실제 QR 컴포넌트의 격리 브라우저 시연에서 큰 QR, 전체 화면, 닫기 후 원래 버튼 초점 복귀, 만료 및 닫힌 초대의 QR 제거를 확인했다.
- 실제 ReactDOM 검사에서 새 진입 코드 입력, 사용자 수정 유지, 추가 네트워크 요청 0회를 확인했다. QR dialog 검사에서 언어 변경 시 재생성 없음, 전체 화면 거절, 오래된 QR 응답 무시를 확인했다.

## 남은 범위와 롤백

- 서로 다른 물리 기기의 Electron 방송과 카메라 스캔을 함께 수행한 현장 E2E는 아직 하지 않았다. 기존 방송 유지와 동일 계정 복원은 실제 함수 실행 및 소유권·미디어 호출 경로 검토로 확인했다.
- QR 자체가 공개된 초대 수단이므로 세션 입장을 허용하려는 범위에서 화면을 공유해야 한다. 입장 만료·닫힘 검증은 계속 서버가 수행한다.
- 이 변경은 프런트엔드와 URL 해석에 국한된다. 해당 변경만 되돌리면 기존 초대/방송/DB 데이터에 영향 없이 원래 화면으로 돌아갈 수 있다.
- 운영 배포와 Electron 설치 파일 재패키징은 하지 않았다.
