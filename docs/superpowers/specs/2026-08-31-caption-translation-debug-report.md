# 캡션 번역 실패 디버깅 및 배포 기록

## 확인한 원인

이번 조사는 `en 텍스트 번역을 확정하지 못했습니다.` 오류를 대상으로 한다. 모델 업데이트 자체를 원인으로 가정하지 않고, 설치된 앱과 소스의 일치 여부, 실제 모델 응답, 최초 번역·확정·화면 표시·게이트웨이의 결합 경로를 확인했다.

- 동일한 로컬 번역용 키와 합성 문장으로 요청했을 때 3.7 Flash는 6초 안에 응답하지 않았고, 3.6 Flash는 약 1.69초에 영어 번역을 반환했다. 이것은 해당 시점·계정·요청의 측정이며 Google 전체 장애 또는 모델 간 일반적인 성능 차이를 증명하지 않는다.
- 기존 모델별 2.8초 재시도 구조는 정상적인 3~6초 응답도 잘라냈다. 번역 실패의 HTTP 상태·취소·빈 응답은 모두 말줄임표로 돌아가 최종 일반 오류로 합쳐졌다.
- 자막 정지 후에도 다음 모델을 두 번 더 호출하는 취소 누락을 로컬 재현했다.
- 한 글자 발화와 문장 다듬기 off 설정에서 최초 번역 자체를 건너뛰었다.
- 번역 한 문장의 실패에 화면이 전체 자막을 종료·삭제하거나 Live Call을 재연결했다. 원문 수신 중 번역 대기를 정체로 오인하는 감시 동작도 있었다.
- Live Gateway의 실제 세션 실행기는 `contents/config`만 받는데 어댑터가 `model`을 추가해 API 이전에 `INVALID_GEMINI_DISPATCH`로 거부됐다. 번역·보정 모두 실제 결합 시험으로 재현했다.
- 짧은 다른 문자권의 출력, 한 글자 원문 복사, `MAX_TOKENS` 등 불완전 응답이 확정될 수 있었다.

## 적용한 동작

| 작업 | 모델 / 정책 |
|---|---|
| 음성 원문 인식 | Gemini 3.5 Transcribe Live 유지 |
| 자막 번역 및 선택적 보정 | Gemini 3.6 Flash 명시 고정 |
| 주제·회의 요약·용어집 추출 | Gemini 3.7 Flash 유지 |
| 자막 최종 번역 | 언어별 최초 1회, 후속 보정 호출 없음, 대체 모델 자동 호출 없음 |
| 최종 요청 제한 | 데스크톱과 게이트웨이 모두 최대 6초; 먼저 완료되면 즉시 반환 |
| 중간 자막 | 진행 중 요청 하나와 최신 대기 입력만 유지, 중복 입력 제거, 대기 입력에도 debounce 적용 |
| 취소 | 정지·최종 확정에 따른 중간 요청 무효화·시간 초과가 실제 요청 중단으로 전파 |
| 완료 판정 | 완성 응답 `STOP` 필수; 생각 출력·차단·잘림·빈 결과는 최종 자막으로 사용하지 않음 |
| 화면 | 비치명적 번역 오류는 기존 자막과 기록을 보존하고 원인 안내; 그 오류만으로 중지·재연결하지 않음 |

기존 모델 설정은 새 자막 모델과 일치하도록 정규화한다. 모델 지문 검증은 완화하지 않으므로 구버전 앱의 3.7 자막 지문은 새 게이트웨이에서 거부된다. 웹·게이트웨이·Mac 앱을 함께 갱신해야 한다. 과거 기록의 모델 정보는 변경하지 않는다.

근거: [3.6 Flash 공식 모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.6-flash), [공식 오류 처리 안내](https://ai.google.dev/gemini-api/docs/troubleshooting), [완료 사유 API 계약](https://ai.google.dev/api/generate-content#FinishReason).

## 검증

- 루트 테스트 1,439 통과, 환경 의존 5개 제외. 웹 861 통과. 게이트웨이 526 통과.
- 타입 검사 통과. 별도 lint 스크립트 없음.
- 실제 합성 한국어 음성 1.86초를 Transcribe Live → 영어 번역 → 최종 자막까지 처리했다. 출력: “We will now begin today's meeting.”
- 실제 게이트웨이 SDK + 세션 실행기 + 번역 어댑터의 번역 요청 1회 성공. 약 3.61초, 입력 297 / 출력 9 / 합계 306 토큰. 기존 3.5초 제한을 넘는 실제 정상 응답을 확인했다.
- 중간 요청 취소 빈도 개선 전 실제 음성 시험은 6회, 단일 비행 보완 후는 3회(중간 2·최종 1)였다. 마지막 debounce 보완은 로컬 시험에서 인접 최종 발화 직전 불필요한 중간 요청을 제거했다. 마지막 보완 이후 유료 음성 시험은 반복하지 않았다.
- 정지 후 추가 요청 0, 이전 세션 자막 발행 0, 요청 취소 및 오류 응답 본문 정리 확인.
- 실제 실행기 결합 시험에서 모델·세션·작업 종류 임의 변경은 API 호출 전에 거부, 정상 요청은 1회만 실행.
- 코드·가짜 응답 테스트와 실제 API 시험을 구분했으며, 고객 녹음·회의 본문·운영 테스트 회의는 사용하지 않았다.

## 적대적 검증과 한계

| 구분 | 결과 |
|---|---|
| 동시 요청·중단 | 중간 요청 단일 비행, 정지 후 추가 요청 0, 오래된 결과 발행 0 |
| 권한·모델 경계 | 세션에 고정된 모델/작업만 허용, 임의 override 거부 |
| 외부 오류·입력 | 안전한 오류 코드만 전달, HTTP 본문·키·발화가 오류 메시지에 포함되지 않음 |
| 짧은 입력 | 한 글자 번역 허용, 다른 문자권·원문 복사 차단, 숫자·정상 짧은 번역 유지 |
| 상태 잔류 | 자막 오류로 세션·확정 표시·기록을 삭제하지 않음 |
| 변경 없는 경계 | DB 스키마·인증·CSRF·SSRF·모바일 경로에 런타임 변경 없음; 기존 웹 회귀 통과 |

장시간 입력이 번역 처리 속도를 지속해서 초과할 때 기존 최종 번역 대기열이 누적되는 구조는 남아 있다. 임의로 문장을 버리면 원문 기록까지 유실될 수 있어 이번 수정에서 대기열 상한·삭제 정책을 추가하지 않았다. 따라서 모든 상황의 비용·메모리 상한을 보장했다고 표현하지 않는다. 중간 자막 요청은 최종 번역 외 별도 호출이며 무료가 아니다. 요약의 기존 제한된 대체 모델 경로는 유지하되, 인증·한도·파싱 오류에는 이어서 호출하지 않도록 강화했다.

미사용 SSE 생성 함수의 EOF 정책은 이번 실제 캡션 경로와 무관하여 변경하지 않았다. 실제 사용자 마이크·장시간 회의·외부 참여 기기의 배포 후 통합 동작은 별도 현장 확인이 필요하다.
