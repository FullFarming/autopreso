# 호스트 로그인 유지 및 로그인 제한 수정

2026-08-31 KST. 사용자가 지정한 `noel` 계정 설정, 설치 앱의 최초 웹 로그인, 재실행 후 로그인 유지 요청을 처리했다. 직전의 재빌드·배포 승인을 적용했다. 비밀번호는 이 문서나 소스에 기록하지 않는다.

## 원인과 변경

기존 Electron은 세션을 확인하는 대신 저장된 비밀번호로 반복 로그인했다. 성공한 로그인도 IP·계정 한도를 소비해 정상 사용 중 제한에 걸릴 수 있었다. 제한 자체를 해제하지 않고 자동 비밀번호 제출을 제거했다.

- 운영 비밀번호는 scrypt 해시로 설정했다. 기존 평문 환경변수는 제거했고 `SESSION_SECRET`과 다른 서비스 자격 증명은 유지했다.
- 최초 실행은 실제 운영 웹 로그인 창을 연다. 로그인 검증과 쿠키 저장이 끝나기 전에 로컬 기능·마이크·오버레이를 시작하지 않는다.
- Electron 기본 세션의 보호된 쿠키를 재사용한다. 원격 로그인 창에는 preload·Node 권한·미디어 권한을 주지 않는다. 인증 후 원격 관리자 화면으로 이동하기 전에 차단하고 로컬 대시보드를 연다.
- 쿠키는 30일 유효하고 남은 기간이 7일 이하일 때만 갱신한다. 최초 인증으로부터 90일을 넘겨 연장하지 않는다. 웹과 앱 모두 만료 경계에서 동일한 만료일을 반복 갱신하지 않는다.
- 웹 보호 화면에서만 상태를 확인한다. 참가자 화면과 QR 전시 화면에는 갱신 루프가 없다. 네트워크 실패 시 쿠키를 지우거나 자동 재로그인하지 않는다.
- 명시적 로그아웃은 진행 중인 갱신 응답이 끝난 다음 쿠키를 지운다. Electron은 활성 통화·진행 중 AI 작업이 있으면 로그아웃을 거절한다. 성공한 로그아웃 후 프로세스를 다시 시작해 이전 계정의 메모리 상태를 버린다.
- 로그인·로그아웃 중 새 통화·자막·Coach·Interpreter 시작을 차단한다. 지연된 AI 콜백도 진행 중 작업으로 추적한다.
- 429 응답은 서버의 Retry-After에 맞춰 안내한다. 연타와 자동 재시도를 막되 정상적인 수동 재시도는 제공한다.

## 검증과 배포

- 웹 테스트 763 + 77 PASS, 웹 타입 검사 PASS.
- 실제 React 검증: 429 연타 시 1회 요청, 대기 만료 후 자동 제출 0회, 언어 변경으로 추가 요청 0회, 숨긴 화면 확인 중단, 실패한 로그아웃 시 화면 이동 0회.
- 무인증 세션 조회 401, 위장 Origin의 갱신 요청 403. 만료·서명 변조·계정 허용 목록 제거·갱신과 로그아웃 경합 테스트 통과.
- 실제 운영 웹 로그인 성공 후 새로고침과 새 탭에서 인증 유지 확인. 이 과정의 비밀번호 로그인 요청은 1회였다. 테스트 회의 생성이나 음성·AI 호출은 하지 않았다.

- Mac ARM64 앱에서 최초 운영 웹 로그인 화면과 `Current account: noel` 표시를 직접 확인했다. 프로세스 종료 후 다시 실행하면 로그인 화면 없이 로컬 대시보드로 진입했고, 서버 로그인 요청 수는 재실행 전후 동일했다. 종료 재진입 방어와 다음 이벤트 순서로 종료하도록 보완한 최종 설치본은 prepare → ready → will-quit → quit 단계 후 프로세스 exit 0을 확인했다.

## 제한과 복구

- 로그인 유지가 무기한 인증을 의미하지 않는다. 30일 미사용 만료 또는 최대 90일 경계에서는 다시 로그인해야 한다.
- 현재 인증은 서명된 쿠키 기반이다. 로그아웃은 해당 기기의 쿠키를 삭제하며 이미 복제된 토큰을 서버에서 즉시 폐기하는 세션 목록은 없다. 계정 허용 목록 제거 시 기존 토큰도 거부된다.
- 로그인 시도 보호를 유지했다. 비밀번호 로그인은 IP 5회/15분, 계정 10회/15분, 전역 120회/5분이며 반복 실패 제한도 유지했다. 기존 제한 버킷 삭제나 보안 키 교체로 우회하지 않았다.
- 기존 로컬 설정·작성 중인 세션 초안·이전 암호화 로그인 파일은 보존한다. 이전 암호화 비밀번호는 자동 복호화하거나 제출하지 않는다.
- 웹 이전 배포는 `dpl_93Dd71otFd5vuPtqaMWq5gezc4aj`이다. 이전 배포로 복구하면 그 배포의 이전 환경 스냅샷도 적용되므로 요청한 새 비밀번호 설정까지 유지하려면 현재 해시 환경으로 이전 소스를 다시 빌드해야 한다.
- 이번 수정은 웹과 Electron 인증 경계이며 게이트웨이·DB 스키마는 변경하지 않는다. 직전 전체 배포의 게이트웨이와 데이터베이스를 유지했다.

검증 로그: `/tmp/nova-auth-*`, `/tmp/nova-desktop-auth-*`.
