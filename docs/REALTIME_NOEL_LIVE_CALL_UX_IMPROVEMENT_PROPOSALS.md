## 1. P0 — 스테이지 대기실 재설계 (제목 + 배경 이미지 + 카운트다운 + QR + 로딩 모달)

사용자 요구: 제목·이미지 업로드·시간 설정 → 시작하면 화면이 전체화면에 가깝게 커지며
카운트다운 + QR + 유튜브 라이브식 로딩 연출이 계속 보이고, 호스트가 Start를 누르면 사라지고 자막 화면으로 전환.

### 1.1 데이터 모델: 커버 이미지 (신규 계약 **C10**)

- `live_sessions.cover_image_path text null` — 추가형 마이그레이션 1건.
- 저장소: Supabase Storage 비공개 버킷 `live-covers/` + 세션 조회 시 signed URL 발급
  (스테이지는 호스트 쿠키, 뷰어는 snapshot 경유로만 노출 → 세션 밖 유출 방지).
- 업로드 API: `POST /api/live-sessions/[id]/cover` — 호스트 소유권 + Origin/CSRF 가드(기존
  미들웨어 패턴 재사용), MIME `image/jpeg|png|webp` 화이트리스트, **5MB 상한**, 서버측 재검증.
  실패해도 세션 생성/시작을 막지 않는다(베스트 에포트 — 기본 자막 무중단 원칙과 동형).
- `CreateLiveSessionInput`에 넣지 않고 별도 업로드로 분리 → 생성 폼은 가볍게 유지, 이미지는 나중에 교체 가능.

### 1.2 스테이지 화면 연출 (LiveStageView 개편)

레이어 구조(아래→위):

```
[1] cover image (object-fit: cover, blur 0 · 원본)
[2] 어둡게 오버레이 (radial gradient, 가운데 60% 투명 → 가장자리 rgba(0,0,0,.72))  ← 자막 대비 확보
[3] 콘텐츠: 제목(상단) · 카운트다운(중앙, 대형 타이포) · 로딩 링(카운트다운 주위 회전) ·
    QR + 6자리 코드(우하단 카드) · "N joined"(좌하단)
```

- **로딩 모달/링**: 유튜브 라이브의 스피너처럼 카운트다운 숫자를 감싸는 인디터미네이트 링을
  `preparing` 상태 내내 회전시킨다(CSS `conic-gradient` + `@keyframes`, JS 불필요).
  카운트다운 0 이후에도 링은 계속 돌고 문구만 "Ready — waiting for host"로 교체 → "죽은 화면" 느낌 제거.
- **전체화면 확대 전이**: 대시보드에서 스테이지를 열 때 작게 나타났다가 0.4s ease로 스케일업하는
  entrance 애니메이션(`transform: scale(.92)→1` + fade). Electron 경로는 이미 확장 디스플레이
  전체화면(C8)이므로 브라우저 폴백에서는 `requestFullscreen()` 버튼을 함께 노출.
- **Start 시 전환**: `session-status: live` 수신(현재 5초 폴링 → §1.3) 시 카운트다운/QR/로딩 레이어를
  0.6s fade-out, 기존 자막 스테이지가 fade-in. 이미지는 옵션으로 5% 투명도의 워터마크로 잔류시킬 수 있게
  토글(기본: 완전 제거 — 자막 가독성 우선).
- **테마**: 1차는 단일(다크) 테마. 유튜브식 테마 선택은 후순위(P3)로 별도 항목화.

### 1.3 스테이지 실시간화

현재 스테이지는 5초 REST 폴링(`LiveStageView.tsx:73`)이라 Start 전파가 최대 5초 늦는다.
뷰어와 같은 broadcast 채널(`session-status` 이벤트)을 구독하도록 바꿔 **Start 즉시 전환**.
폴링은 폴백으로 유지(재사용: `connection-resilience.ts`).

### 1.4 테스트 (TDD)

- `cover` 라우트: 소유권/사이즈/MIME 거부, 성공 시 path 저장 — `lib/live` 단위 테스트.
- 스테이지 상태 전이: preparing(카운트다운)→ready(0 이후)→live(레이어 제거) 순수 로직 분리 후 테스트.
- 기존 `formatCountdown` 테스트 유지.

## 2. P0 — 모바일 뷰어(라이브콜 웹) 대기실 카운트다운 (신규 계약 **C11**)

사용자 요구: 라이브콜 웹에도 카운트다운.

- `LiveSnapshot.session.scheduledAt`이 이미 뷰어에 온다(`LiveViewer.tsx:62,167`) → 서버 변경 불필요.
- 대기 화면을 텍스트 1줄에서 **미니 스테이지**로 확장: 커버 이미지 배경(C10 signed URL을 snapshot에 포함)
  + 제목 + 동일 `formatCountdown` 카운트다운 + 로딩 링. 검정 풀스크린 원칙 유지.
- 카운트다운 0 이후: "곧 시작합니다 — 호스트를 기다리는 중" + 링 유지. **뷰어에서도 자동 전환 없음**;
  `session-status: live` 수신 시에만 자막 화면 전환(이미 있는 경로).
- 시계 편차 보정: 뷰어 기기 시계가 틀릴 수 있으므로 snapshot 수신 시 `serverNow`를 한 번 내려
  offset을 잡는다(신규 필드 1개, 없으면 로컬 시계 폴백).
- 시작되면 기존처럼 자막이 기록·표시된다(파이프라인 변경 없음 — live 전환 시점부터 `live_utterances` 영속은 현행 그대로).

## 3. P0 — 자막 피드 역순: 최신이 맨 위 (신규 계약 없음, 클라 전용)

사용자 요구: 최근 번역이 제일 위, 오래된 것이 아래로 밀리는 방식.

- 현재 `ViewerStage`(`LiveViewer.tsx:486-556`)는 최신이 아래 + pin-to-bottom.
- 변경: **newest-first 렌더링**.
  - partial(진행 중) 자막을 최상단 고정 슬롯에, 확정 자막을 그 아래 최신→오래된 순으로.
  - 스크롤 기준 반전: 사용자가 위(최신)에 있으면 pinned; 아래로 내려가 과거를 읽는 중이면
    새 자막이 와도 스크롤 유지, `live-jump-latest` 버튼은 "맨 위로"로 동작( bottom→top 재배치).
  - 구현은 배열 reverse 렌더 + scrollTop 기준(0 근처=pinned)으로. `flex-direction: column-reverse`는
    스크린리더 읽기 순서가 시각 순서와 어긋나므로 **사용하지 않는다**.
  - `aria-live` 영역은 최신 자막 텍스트만 담는 시각적으로 숨긴 노드로 분리(중복 낭독 방지).
- 어닝콜 앱 관행과 일치: 실시간 콜 트랜스크립트 UI는 최신 발화가 위에 쌓이는 피드형이 일반적
  (시선 고정 위치가 항상 화면 상단 = 폰을 든 자세에서 엄지 간섭 없음).
- 기존 `slice(-200)` 링버퍼, seq dedupe, replay 병합은 그대로 재사용.
- 테스트: 정렬/pinned 판정 로직을 순수 함수로 추출해 단위 테스트 (`ordering.test.ts`).

## 4. P1 — Speak 버튼 확대·승격

사용자 요구: Speak 버튼이 더 크게.

- 현행: speak-bar 우측 pill `min-height 46px`(`globals.css:589`).
- 변경:
  - 발언권이 **비어 있을 때**: speak-bar를 버튼 중심으로 재구성 — 최소 **56px 높이, 화면 폭 60% 이상**의
    대형 버튼(iOS 최소 터치 타깃 44pt의 1.3배). 하단 안전영역(`env(safe-area-inset-bottom)`) 위 고정.
  - **다른 사람이 발언 중**: 버튼을 줄이는 대신 발언자 표시(웨이브 + 이름)를 주 정보로, 버튼은 보조로 축소.
  - **내가 발언 중**: 현행 red pulse 유지 + 크기 유지(놓치지 않고 끝낼 수 있게), 라벨 "End speaking".
  - 역순 피드(§3)와 궁합: 피드가 위에서 자라므로 하단 버튼 영역과 시선 충돌 없음.
- 접근성: `aria-pressed`, 상태 변화 시 `role="status"` 안내 유지.

| # | 개선안 | 요지 | 난이도 |

| A3 | **동기화 상태 인디케이터** | 마지막 자막 수신 후 N초 경과 시 "re-syncing…" 미세 표시 → gap-fill(C2)이 도는 동안 사용자 불안 제거 | 하 |

| A5 | **트랜스크립트 내려받기** | 종료 화면에서 언어별 전문 TXT/MD 다운로드(참가자용). 회의록(C7)과 별개로 원문 로그 제공 | 하 |
| A6 | **입장 전 오디오 체크** | 번역 음성 On 선택자에 한해 조인 직전 짧은 테스트 톤 재생 → 무음 이어폰 이슈를 시작 전에 발견 | 하 |
| A7 | **스테이지 카운트다운 테마** | 유튜브식 테마(calm/dramatic 등) 2~3종. 커버 이미지와 조합되는 오버레이 팔레트 프리셋 | 중 |

| A9 | **재접속 토스트 일원화** | 소켓 재접속/replay 중 상단에 1줄 토스트("Reconnecting — captions will catch up"). connection-resilience에 UI 배선 | 하 |

스코프가 크고, 사내 어닝콜 성격과 충돌. 필요해지면 별도 기획으로.

| 하단 시트 라이브 자막 | 접기(∨)/닫기(X) 가능한 시트에 실시간 번역 문장이 흐르고, 하단에 `가이던스 · 경영진 발언 중` + 오디오 웨이브. 다른 화면을 브라우징하면서도 시트 유지 | 부분 반영(발화자 시트+웨이브). **접기/유지 브라우징은 미반영** |
| 발표 내용 탭 | 발화 카드(발화자·타임스탬프)마다 **요약보기/원문보기** 토글, 좋아요 | 원문은 회의록 트랜스크립트에 있음. 카드별 요약 토글 미반영 |
| 한\|EN 토글 상단 우측 | 시청 언어 즉시 전환 | 반영됨(뷰어 언어 스위치) |
| 세션 구간 라벨 | "가이던스", "Q&A" 등 진행 구간 표시 | 미반영(후속 아이디어) |
| 오디오 진행바 | 라이브 스트림 위치 표시 | 해당 없음(우리는 현장 라이브) |

**개념 확정(사용자 지시)**: 자막이 主, Live Call은 그 위의 옵션. 자막 언어 설정이 Live Call 언어가 되고,
인입 언어는 자막처럼 자동 감지. 참가자는 웹에서 자기 표시 언어만 선택한다. 데스크톱 Live Call 페이지는
2026-07-23에 이에 맞게 수정됨: 일정/시간은 모달로, 언어 섹션은 자막 언어 미러(읽기 전용 칩)로.
