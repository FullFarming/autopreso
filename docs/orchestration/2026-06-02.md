## Objective
Make `Realtime Noel` usable as an Electron tool that captures system audio and/or microphone input, sends it to OpenAI Realtime translation, and shows uninterrupted English <-> Korean subtitles in the overlay.

## Discussion Record
- CTO hub asked the API reviewer for read-only analysis of OpenAI Realtime wire shape, bidirectional routing, required tests, and reliability risks.
- CTO hub asked the UX reviewer for read-only analysis of first-run flow, audio permission failures, overlay reliability, and demo failure scenarios.
- API reviewer initially flagged the translation wire shape as likely incompatible. CTO hub verified the endpoint directly with the real OpenAI Realtime translation API before accepting or rejecting that claim.
- UX reviewer flagged first-run permission friction, API key preflight, audio signal visibility, and overlay robustness as the highest-impact user failures.

## CTO Decisions
- Accepted: keep the current OpenAI Realtime translation endpoint because the live API probe returned `session.updated` and produced EN -> KO and KO -> EN translated audio transcripts.
- Accepted: do not open an OpenAI subtitle session until local audio capture has succeeded. This avoids API sessions being created when macOS permission prompts or input devices fail.
- Accepted: status messages must not overwrite an active subtitle line. The overlay now suppresses transient status rendering while a real subtitle is fresh.
- Accepted: protect the overlay window from screen capture with Electron `setContentProtection(true)`.
- Accepted: surface silent audio input and overlay websocket disconnects as visible overlay warnings instead of failing quietly.
- Accepted: validate OpenAI Realtime connectivity before saving a newly-entered API key. The key is not returned to the client or written to logs.
- Accepted: treat OpenAI Realtime socket transport errors as recoverable reconnect states, not fatal dashboard stops.
- Deferred: redesign from two target-language channels to a single detected-language routing channel. It may reduce cost, but it changes core streaming behavior and needs a separate API proof.
- Deferred: explicit `input_audio_buffer.commit` on every turn. The current live translation probe worked without it; changing this requires a focused protocol test.
- Deferred: full dashboard redesign into a single bilingual toggle. Current routing already handles EN <-> KO with regression tests; simplifying the UI is not a release blocker.
- Rejected: the claim that the current Realtime translation endpoint is release-blocking. It was disproved by a live handshake and synthetic EN -> KO / KO -> EN translation probe.
